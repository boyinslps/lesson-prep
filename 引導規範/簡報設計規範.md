# 簡報設計規範（把引導軌跡視覺化 × 精確 AI 生成控制）

> 這份文件寫的是**過程的邏輯**與**如何精確驅動 AI 產出投影片**，不是某主題的模板。
> 目標：拿到任何主題的一段引導軌跡，能（1）決定它該長成怎樣的投影片、（2）寫出一段
> **能精準控制頁數／文字／風格／舉例／圖示**的 AI 生成指令。
>
> **使用原則**
> - 例子一律標「〔例，換主題請重推〕」，只為說明邏輯。
> - 先讀 `教學活動設計規範.md`：投影片是把那裡的**引導軌跡**外顯出來，兩份要一起用。
> - 風格證據與真實頁面拆解在 `../教學風格分析.md`（Part 4-D 三種視覺語域、Part 5.3/5.4）。

---

## 1. 核心：一張投影片 ＝ 軌跡上的一步

投影片不是「把講稿貼上牆」，而是**把引導軌跡外顯成一格一格**——每一頁推進學習者**一個**認知動作。
所以簡報設計的第一原則是：**一頁一動作（one idea per slide）**。頁與頁的關係，就是軌跡上狀態轉移的關係。

推論：
- **頁數不是先決定的，是從軌跡的步數長出來的**。有幾個「非跨不可的認知動作」，就有幾頁（再加開場與收束）。
- 一頁塞多個重點 = 把兩步併一步 = 破壞引導節奏。寧可多一頁，不要擠一頁。
- 投影片的順序 = 引導的順序（先需求後功能、先比喻後操作、先預測後揭曉）。

## 2. 從引導軌跡投影成頁面序列

把 `教學活動設計規範.md` 的**引導操作子（G1–G9）**投影成**頁面功能型**。功能型是「這頁在引導中負責什麼」，不是固定版型。

| 引導操作子 | 對應頁面功能型 | 這頁要做到 |
|---|---|---|
| G1 製造勢能差 | **鉤子頁** | 一張對比圖／衝擊畫面 ＋ 一句驅動問句 |
| G2 接舊橋新 | **承接頁** | 複習上一步 ＋ 拋出舊法解不了的新問題 |
| G3 具象化抽象 | **解密頁** | 一個承重比喻的圖解 ＋ 一句金句 |
| G5 讓目的地可檢核 | **定向頁** | 今日目標（2–3 條）＋ 一句通關條件 |
| G4 降低起步門檻 | **步驟頁** | 編號操作或半成品；標按鈕名／快捷鍵 |
| G6 預測—驗證 | **挑戰頁** | 一個「你猜會怎樣？為什麼？」的問題 |
| （單元任務） | **任務頁** | 明確任務 ＋ 繳交前自我檢查清單 |
| G8 給界線 | **界線頁**（涉 AI/工具才有） | 查核方式／隱私紅綠燈／來源版權 |
| G9 產出展示 | **收束頁** | 發表方式 ＋ 具體回饋句型 |

> 一段軌跡不必用滿所有功能型；依內容取用。步驟頁常會有多頁（一步一頁）。

## 3. 語域與風格：用參數推導，不用固定答案

這位老師的簡報有**三種視覺語域**，選哪種是**推導**出來的，不是固定的：

**決策軸一：內容類型 → 語域**
- 教**具體軟體操作** → **語域①操作截圖風**：真實截圖／照片 ＋ 紅圈紅箭頭指確切按鈕 ＋ 編號步驟 ＋ 快捷鍵醒目 ＋ 介面分區命名。
- 教**抽象概念／程式邏輯** → **語域②概念插畫風**：主題化插畫、承重比喻圖、手繪積木、冒險／關卡框架。
- 兩者混合的課 → **語域③混合**：插畫講概念、截圖講操作，同一份切換。

**決策軸二：年級 → 美術主題（風格 token 的起點）**
- 中年級（如四年級）：明亮、可愛、暖色、圓體、方格紙感。
- 高年級（如五年級）：酷炫、深色、霓虹、科幻感。
- （這是起點值，可依班級氣質微調。）

**風格 token（把風格變成可填變數，交給 AI 才控得住）**
```
情緒基調 = 〔如：冒險闖關 / 溫馨手作 / 偵探解謎〕
主色系   = 〔如：深藍＋霓虹青 / 米白＋暖橘〕
強調色   = 〔關鍵字上色用〕
字體感   = 〔如：圓潤可愛 / 俐落科技〕
插畫風格 = 〔如：像素電玩 / 3D 玻璃擬物 / 扁平手繪〕
版面密度 = 〔低＝留白多、字少；越低年級越低〕
產製工具 = 〔如 NotebookLM 生成插畫簡報 / 手動截圖標註 / AI 生成 HTML〕
```

> 風格的作用是**服務理解與投入**，不是裝飾。一份簡報**風格 token 要一致**，才不會東拼西湊。

## 3.5　生產模式與顆粒度（本規範最容易做錯的兩件事）

### 生產模式：簡報用 NotebookLM 生成，本規範只控「頁序＋文字」
- 教學簡報實際用 **NotebookLM** 產出（含視覺）。因此**視覺由生成器自己決定，我們不指定 emoji、不逐頁畫圖示**。
- 我們能精準控制的是：**頁面序列（幾頁、每頁講什麼、順序）** 與 **每頁文字**。這兩者透過「頁面清單 manifest ＋ 文字預算」交給 NotebookLM。
- **不要在 manifest 放 emoji 或「圖示需求」欄**。若某頁的視覺很關鍵（如需要真實截圖標註紅箭頭），改用一句**視覺意圖**文字描述（見 §4.5），讓生成器理解，而不是塞 emoji。

### 顆粒度：拆到「一頁一個微步驟」——這是與真實簡報最大的差距
> **對照分析（真實簡報 vs 先前草稿）**
> - 真實簡報《G5 地圖找障礙》13 頁：**光「引發問題」就用 7 頁**（驅動問句→短影片→找障礙 I-spy→障礙照片牆→改善設計×2→改造前後對比）；**「街景截圖」這一個操作用 5 頁**（開地圖→切街景→剪取工具→儲存vs複製→框選拖曳），一頁一個子動作。
> - 真實簡報《G5 表單設計》24 頁：三種題型**各佔一頁**（選擇題／下拉式／核取方塊），校長情境的「轉成問題」概念**跨 4 頁**慢慢鋪。
> - 先前草稿：一節壓在 5–12 頁，把「登入」這種多步操作塞成 1 頁——**太粗，約差 2–3 倍**。

**拆碎規則（務必遵守）**
1. **一頁一個微步驟**：一次點擊、一個新想法、一個例子＝一頁。若一頁出現「步驟1…步驟2…步驟3」，通常就該拆成 3 頁。
2. **操作拆到點擊層級**：把一個操作（如「截圖一個地點」）拆成它的每一個子動作，每個子動作一頁。
3. **可列舉的變體各佔一頁**：每種題型、每個選單選項、每個效果——一個一頁，不要並排擠成一頁。
4. **引發問題階段要給足頁數**：多個例子、對比、真實案例，各自一頁，慢慢累積「有感」——不要一頁帶過。
5. **概念用比喻時可跨多頁鋪陳**：一個承重比喻可以用 2–4 頁一步步展開（拋問→比喻→套用→驗證）。
6. **加銜接頁**：概念與概念之間、操作段落之間，放一頁**過場/承接**（複習剛才→帶到下一步），讓節奏有停頓、學生跟得上。

## 4. ★ 精確 AI 生成控制系統

直接叫 AI「幫我做一份○○簡報」，它的預設失控模式是：**頁數暴衝、每頁字爆量像文件、風格每頁漂移、舉例空泛通用、圖示亂放或與內容無關**。
本節給你**五個控制軸**，把這五件事一一夾住。核心手法是**兩段式生成**：先產「頁面清單」審核，再逐頁展開。

### 4.0 兩段式生成（控制的總開關）
> 這是頁數與文字失控的最強解法：不要讓 AI 一次噴出整份簡報。

1. **第一段——先產頁面清單（manifest）**：要求 AI 只輸出一張表，逐頁列
   `{頁碼 · 功能型 · 這頁一句話任務}`（**不放圖示欄、不放 emoji**；視覺交給 NotebookLM）。依 §3.5 拆到一頁一微步驟。**人（你）審核、增刪、調序。**
2. **第二段——逐頁展開**：清單定案後，才叫 AI 依每頁的功能型與**文字預算**把內容寫滿，一頁一頁生成，不准自行加頁。

### 4.1 頁數控制軸
- **原則**：**一頁一個微步驟**（見 §3.5）；多一頁永遠勝過擠一頁。頁數是「拆到夠碎」後自然的結果，不是先設上限。
- **頁數期待值（校準用，非上限）**：一節操作型簡報約 **15–25 頁**；引發問題階段常 5–8 頁，一個多步操作 4–6 頁，每種變體各 1 頁。**若你的清單只有 8–12 頁，八成是拆得不夠碎，回頭把每個「步驟N」拆成獨立頁。**
- **寫進 prompt 的句型**：
  「先只輸出**頁面清單**：逐頁列出【頁碼｜功能型｜一句話任務】（不要圖示欄、不要 emoji）。**一頁只做一個微步驟**：一次點擊、一個新想法、一個例子就是一頁；凡出現『步驟1…2…3』一律拆成多頁；每種題型／選項／變體各一頁；引發問題與比喻可跨多頁鋪陳。**先不要寫內頁內容**，等我確認清單。」

### 4.2 文字控制軸
- **原則**：投影片是**提示**不是講稿；把話留給老師的嘴，牆上只放關鍵。
- **可調參數（預設值，越低年級越少）**：
  - 標題：問句或任務句，≤ **全形 14 字**。
  - 內文條列：每頁 ≤ **3 條**，每條 ≤ **全形 16 字**，關鍵詞或動詞開頭。
  - 步驟頁：一頁 ≤ **3 步**，每步一行祈使句 ≤ **全形 18 字**，標出**按鈕名／快捷鍵**。
  - 每頁只有 **1 個重點**；比喻用 **1 句金句**。
- **硬性禁止**：整段敘述、把講稿寫上頁、一頁多重點、密密麻麻的說明文字。
- **寫進 prompt 的句型**：
  「文字預算：標題 ≤14 全形字且為問句或任務句；每頁條列 ≤3 條、每條 ≤16 全形字、關鍵詞開頭；**禁止整段文字與多重點**；步驟頁每步一行祈使句並標按鈕與快捷鍵。超出預算就精簡用詞，不得換行硬塞。」

### 4.3 風格控制軸
- **原則**：用 §3 的**風格 token** 把「風格」變成明確變數，整份一致。
- **寫進 prompt 的句型**：
  「整份維持一致風格：情緒基調＝`__`；主色系＝`__`；強調色＝`__`（僅用於關鍵字）；字體感＝`__`；插畫風格＝`__`；版面密度＝`__`（留白多、字少）。**每一頁都套同一組風格，不得逐頁漂移。**」

### 4.4 舉例控制軸
- **原則**：例子必須是**學習者的真實脈絡**（呼應 G7）；AI 最愛給空泛通用例子，要擋。
- **可調參數**：`在地／個人例子池`（你先列好可用的真實例子）。
- **寫進 prompt 的句型**：
  「所有舉例**只能**從這個清單取用：`〔例子池：…〕`。清單不足時**標「待補例子」**，**不得自行虛構通用範例**。凡能換成學習者自己的場景／資料的地方，都要留成可替換的空格。」

### 4.5 視覺意圖軸（不是「圖示控制」——視覺交給 NotebookLM）
> 簡報用 NotebookLM 生成、**視覺由它決定**。我們不指定 emoji、不逐頁畫圖示、不放圖示欄。只在**少數視覺是理解關鍵**的頁，補一句「視覺意圖」讓生成器抓到方向。
- **多數頁**：不寫視覺，讓 NotebookLM 依內容自動配圖。
- **視覺是關鍵的頁**（例如比喻需要特定圖解、流程需要示意）：補一句**視覺意圖**文字——說明「這頁要幫學生看懂什麼」，而非給 emoji 或裝飾指示。
- **真實截圖類**（NotebookLM 產不出你教室的實際介面）：在該頁標「**視覺意圖：需真實操作截圖（老師補）**」，成品先留佔位，對應 S7 的自製截圖素材。
- **寫進 prompt 的句型**：
  「視覺一律交給生成器自動配，**不要 emoji、不要逐頁指定圖示**。僅在視覺是理解關鍵的頁補一句『視覺意圖：…』；需要真實介面截圖的頁標『需老師補截圖』並留佔位。」

### 4.6 主控生成指令（可填模板）
把五軸合成一段可貼給 AI 的指令。`【】` 是變數，用前先填。

```
你是這位教師的簡報協作者。請依以下規範，為主題【主題】設計一份教學簡報。
這份簡報要把一段「引導軌跡」外顯成一頁一步。

■ 引導軌跡（來自教學活動設計）：
【貼上本課的軌跡：起點→目標，及要推進的幾個引導步驟/操作子】

■ 語域與年級：語域＝【①操作截圖／②概念插畫／③混合】；年級＝【中/高年級】。（產製工具＝NotebookLM，視覺交給它）

■ 舉例池（只能用這些，不足標「待補」，禁止虛構通用例子）：
【列出在地／個人真實例子】

■ 產出方式（務必兩段式）：
  第一段：先只輸出【頁面清單】，逐頁列「頁碼｜功能型｜一句話任務」（不要圖示欄、不要 emoji）。
          **拆到一頁一個微步驟**：一次點擊／一個新想法／一個例子＝一頁；「步驟1…2…3」一律拆多頁；
          每種題型/選項/變體各一頁；引發問題與比喻可跨多頁。操作型一節約 15–25 頁。先不要寫內頁，等我確認。
  第二段：我確認清單後，再逐頁展開，遵守文字預算：
          標題≤14全形字(問句/任務句)；每頁條列≤3條、每條≤16全形字、關鍵詞開頭；
          步驟頁每步一行祈使句≤18全形字並標按鈕/快捷鍵；每頁1重點；禁止整段文字。
  視覺一律交給 NotebookLM 自動配；僅在視覺是理解關鍵的頁補一句「視覺意圖：…」，需真實截圖的頁標「需老師補截圖」。
```

## 5. Few-shot 示範

> 以下用**分析語料外的新主題**示範「軌跡 → 頁面清單 → 生成指令」的推導。看推理，不要背內容。
> ⚠️ 註：下表為**早期示意**，仍畫了「圖示需求」欄且頁數偏少。**現行規則以 §3.5／§4 為準**：manifest 不放圖示欄與 emoji、視覺交給 NotebookLM、且要拆到一頁一微步驟（操作型 15–25 頁）。此表僅供理解「軌跡→頁面」的對應關係。

### 示範一：主題「用 Google 試算表管理班費」（語域③混合、中年級）

**（a）先把軌跡投影成頁面清單（manifest）— 這是第一段輸出**

| 頁 | 功能型 | 一句話任務 | 圖示需求 |
|---|---|---|---|
| 1 | 鉤子頁 | 亂記紙本 vs 一改就自動算的表格，問「你想手算還是讓電腦算？」 | 左右對比圖，扁平手繪，16:9 |
| 2 | 承接頁 | 複習「文件會打字」，拋「但它會幫你算數學嗎？」 | 文件圖示打叉、試算表圖示打勾，emoji |
| 3 | 解密頁 | 比喻：儲存格＝抽屜，公式＝抽屜間的管線 | 抽屜＋管線圖解，1 句金句 |
| 4 | 定向頁 | 通關條件：改任一筆金額，結餘會自己變且算對 | 目標小旗圖示 |
| 5 | 步驟頁 | 步驟：①輸入日期項目 ②填收入/支出 ③套 =SUM() | 試算表截圖＋紅圈紅箭頭 |
| 6 | 挑戰頁 | 「我改上面的數字，你猜結餘會怎樣？為什麼？」 | 問號插畫 |
| 7 | 任務頁 | 用半成品表填 3 筆並套加總；附繳交自我檢查 | 檢查清單勾勾 |
| 8 | 收束頁 | 互看，用「我發現你的○○，如果××會更清楚」回饋 | 兩人對話插畫 |

**（b）對應的生成指令重點（第二段）**：語域③；風格 token＝情緒【溫馨手作】‧主色【米白＋暖橘】‧插畫【扁平手繪】‧密度【低】；舉例池＝【本班班費項目：飲water、影印、班遊…】；文字預算如 §4.2。圖示：第 5 頁要真實截圖標註，其餘用扁平手繪小圖。

### 示範二：主題「Scratch：讓角色被鍵盤控制移動」（語域②概念插畫、高年級）

只列軌跡 → 頁面清單的**推理骨架**，示範概念課的頁型節奏：
- 承接頁（G2）：複習「上次角色會自己動」→ 拋「但玩家想**自己控制**它，怎麼辦？」
- 解密頁（G3）：比喻「鍵盤偵測積木＝一直在問『你按了嗎？』的哨兵」。
- 挑戰頁（G6）：「老師先不寫程式，先按方向鍵——你猜要偵測什麼，角色才會動？」
- 步驟頁（G4）：手繪積木：`當按下右鍵 → x 改變 10`，一頁一鍵。
- 任務頁：讓角色能上下左右移動並上傳，檔名＝班級座號；風格 token＝深色霓虹科幻、像素插畫、密度低。

> 兩個主題、兩種語域，但**「軌跡→一頁一步→兩段式生成→五軸控制」的流程一模一樣**。這就是要遷移的東西。

## 6. 生成後自檢（用提問）

- 頁數是不是**從軌跡步數長出來**的？有沒有哪頁其實塞了兩步？（該拆）
- 每頁是不是**只有一個重點**？標題是問句／任務句嗎？
- 文字有沒有超出預算、變成講稿？操作頁有沒有標按鈕與快捷鍵？
- 風格 token 整份**一致**嗎？還是逐頁漂移？
- 舉例是不是**學習者的真實脈絡**？有沒有混進 AI 自己編的通用例子？
- **顆粒度夠碎嗎？** 有沒有哪頁塞了多個步驟該拆開？頁數是不是掉到 8–12 頁（八成太粗）？
- manifest 有沒有不小心留了 emoji／圖示欄？（視覺該交給 NotebookLM）
- 語域選對了嗎（操作①／概念②／混合③）？年級美術主題對嗎？
- 換一個主題，我這套**頁面清單＋生成指令**的做法還走得通嗎？（走得通才算對）
