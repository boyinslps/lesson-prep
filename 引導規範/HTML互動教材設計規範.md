# HTML 互動教材設計規範（把引導軌跡變成「可動手」的學習頁 × 精確 AI 生成控制）

> 這份文件寫的是**過程的邏輯**與**如何精確驅動 AI 產出一頁 HTML 互動教材**，不是某主題的模板。
> 目標：拿到任何主題的引導軌跡，能生成一份**學生自己打開就能操作、有即時回饋、能個人化**的單檔 HTML 學習材料。
>
> **使用原則**
> - 例子一律標「〔例，換主題請重推〕」。
> - 先讀 `教學活動設計規範.md`（引導軌跡與操作子 G1–G9）與 `簡報設計規範.md`（兩段式生成、五軸控制的手法）。本規範是它們的「互動版延伸」。
> - 原型參考：`../分析資料/四年級簡報/Scratch.html`（老師手作的互動教材），拆解見 `../教學風格分析.md` U4-★。

## 1. 核心：HTML 教材 ＝ 把引導軌跡「可操作化」

簡報是把軌跡外顯成**一頁一步讓學生看**；HTML 教材再進一步——把每一步變成**學生自己動手做、系統立刻回饋**的互動。

**簡報 → HTML 的關鍵躍遷：`被動看` → `主動做 + 即時知道對不對`。**

這帶來三個只有 HTML 能給的槓桿（也是選擇做 HTML 而非簡報的理由）：
1. **即時回饋迴圈**：學生一操作，頁面馬上告訴他對／錯／為什麼——把 G6「預測—驗證」變成秒級循環。
2. **做中學**：能拖、能點、能試的東西，不用只用讀的（強化 G4）。
3. **個人化產物**：學生輸入自己的資料，頁面**當場生出屬於他的成果**（強化 G7 擁有感）。

> 判斷「這個主題該做 HTML 而非簡報」的標準：**它有沒有值得學生反覆試、需要即時回饋、或能個人化的環節？** 有 → 適合 HTML。純線性講述 → 簡報就夠。

## 2. 從引導軌跡投影成互動區塊

把操作子（G1–G9）投影成**互動區塊型**。與簡報不同的是：每個概念區塊盡量帶「一個要學生動手的動作」與「一個完成訊號」。

| 引導操作子 | 互動區塊型 | 學生在這區要「做」什麼 | 即時回饋 |
|---|---|---|---|
| G1 製造勢能差 | **情境開場區** | 看對比／點一下切換「問題 vs 理想」 | — |
| G3 具象化抽象 | **比喻演示區** | 操作一個可玩的比喻（拖、點、滑）看概念怎麼動 | 畫面即時反應 |
| G6 預測—驗證 | **即時選擇題區** | 先選答案 | 立刻顯示對/錯 ＋ **為什麼** |
| G4 降低門檻 | **拖曳配對／填空／選單區** | 把積木/步驟拖進正確插槽、或從選單挑 | 對→鎖定並前進；錯→提示再試 |
| G5 通關條件 | **進度／徽章區** | 完成小關解鎖徽章 | 進度條、徽章亮起 |
| G7 在地個人化 | **個人化生成器區** | 填自己的資料（名稱/內容…） | 當場產出**屬於他的**成果／預覽 |
| G8 給界線 | **查核／隱私提示區** | 勾選「可公開 vs 要隱藏」 | 標出紅燈項目 |
| G9 產出展示 | **匯出／分享區** | 複製成果、下載、或秀出來 | 一鍵複製成功提示 |

**版面組織原則（延續原型）**：**一個概念一個色區**（藍/橘/綠/紫…各一色），色彩幫學生分辨「現在在學哪一塊」；由上而下就是引導軌跡的順序。

## 3. 互動樣式庫（可重用的五種互動，AI 照這幾種做就穩）

不要讓 AI 每次自由發明互動。**收斂成這幾種可靠、好生成、好操作的互動**，換主題只換內容：

1. **即時選擇題**：一題 + 選項；點選後立刻變色顯示對/錯，並秀一句「為什麼」。（承 G6）
2. **拖曳/點選配對**：把卡片（積木、步驟、詞）拖進正確插槽；全對才解鎖下一區。行動裝置用「點卡→點槽」取代拖曳較穩。（承 G4）
3. **可玩的比喻演示**：一個小舞台，拖滑桿/點按鈕，即時看到概念行為（如拖物件看座標數字變、按一下看「變數盒子」數字被覆寫）。（承 G3）
4. **個人化生成器**：幾個輸入框 → 按鈕 → 依模板即時組出學生自己的成果文字/預覽（如把他填的景點資料組成導覽台詞）。（承 G7）
5. **進度徽章**：完成各區點亮徽章＋進度條；全通關給一個完成畫面。（承 G5）

> 每個知識點**至少配一個「做」的互動**（1 或 2 或 3 擇一），不要整頁只有讀。

## 4. ★ 精確 AI 生成控制系統（HTML 版五軸）

沿用簡報規範的手法：**兩段式生成 ＋ 五軸夾住**。HTML 版的五軸是：**結構／互動／文字／風格／技術**。

### 4.0 兩段式生成（總開關）
1. **第一段——先產「區塊清單」（manifest）**：只輸出一張表，逐區列
   `{區塊 · 對應概念 · 互動類型(§3的1–5) · 完成訊號 · 色彩}`，一概念一區塊。**你審核、增刪、調序。**
2. **第二段——生成單檔 HTML**：清單定案後，才產出完整 `.html`，不准自行增加區塊或互動。

### 4.1 結構控制軸
- **原則**：一個概念一個色區；由上而下＝引導軌跡順序；頁首一句話說明「這頁要帶你做到什麼」，頁尾是個人化生成器＋匯出。
- **寫進 prompt**：「先只輸出**區塊清單**：逐區列【區塊名｜概念｜互動類型(1–5)｜完成訊號｜色彩】，一概念一區、區塊數 ≤`N`；先不要寫 HTML，等我確認。」

### 4.2 互動控制軸
- **原則**：每個知識點至少一個 §3 的互動；**即時回饋**是必要件（選了/拖了要馬上知道對錯與為什麼）；行動裝置友善（點選優先於拖曳）。
- **寫進 prompt**：「每個概念區塊必含一個 §3 互動（即時選擇題／配對／比喻演示 擇一），作答後**立即**顯示對錯與一句原因；配對全對才解鎖下一區；用點選相容觸控。**不要只有文字說明。**」

### 4.3 文字控制軸（同簡報精神：頁面是提示不是課本）
- **原則**：短、口語、指令式；對小學生說話。
- **可調參數（預設，越低年級越少）**：區塊標題 ≤ **全形 14 字**；每段說明 ≤ **2 行**；按鈕/選項字 ≤ **8 字**；回饋訊息一句話。
- **寫進 prompt**：「文字精簡口語，對小學生；標題 ≤14 全形字；說明每段 ≤2 行；**禁止長段落與課本式敘述**；用『你、我們』與鼓勵語氣。」

### 4.4 風格控制軸
- **原則**：用**風格 token**（同簡報 §3）決定整體視覺；**單檔內一致**；依年級調主題（中年級明亮圓潤／高年級酷炫科幻）。
- **寫進 prompt**：「風格 token：情緒【】、主色系【】、強調色【】、字體感【圓潤可愛/俐落科技】、圓角與陰影【多/少】。整份一致；每個概念一個色區但同一套風格語言。」

### 4.5 技術控制軸（讓 AI 產出「打開就能動」的單檔）
> 這一軸最容易被忽略，卻決定生成品質。**明確規定技術邊界，AI 才不會產出跑不動或依賴外部資源的檔案。**

#### ★ 先決定佈署情境（這決定外部資源能不能用，別搞錯）
> **教訓**：曾把「Artifact 平台不能外連圖」的限制誤套到本機課堂檔上，結果 S7 清單裡的照片、地圖、外部連結全被 emoji 悄悄取代，內容空洞撐不起一節課。**兩種情境的規則相反，動筆前先確認是哪一種。**

- **A. 課堂本機檔（預設）**：用瀏覽器在教室電腦雙擊開啟，**沒有 CSP 限制**。→ **可、且應**使用外部資源把內容做厚：真實景點**照片**、**地圖 iframe**（如 Google 地圖 `...&output=embed`）、**外部網站連結**（如官方旅遊網）。唯一要求：**主結構與互動不因斷網而壞**——外部圖載不出時要有替代文字或 emoji 佔位（`onerror` 退回）。
- **B. 公開發布 / Artifact 平台**：受 CSP 限制，外部資源會被擋。→ 此時才回到「全內嵌」：圖片用 emoji／內嵌 SVG／data URI，外部照片換成開放授權或內嵌版。

**鐵則（兩情境都適用）**：**S7 清單裡採用的視覺素材（照片、地圖、連結）必須實際出現在成品**，不得用 emoji 靜默取代。某素材若尚未取得，用**明確佔位框**標「待補：素材編號」，而不是省略。

- **單一自足檔**：輸出**一個 `.html`**，CSS/JS 全部**內嵌**；不依賴任何**本地**檔或建置流程（外部 CDN／圖床／地圖依佈署情境而定）。
- **字型與框架**：Tailwind CDN（`https://cdn.tailwindcss.com`）＋ 一組 Google Fonts（圓體如 Fredoka／Noto Sans TC）。
- **純前端**：原生 JS，不用框架建置；顯示切換用 `hidden` 屬性或 class，不要重繪整頁。
- **狀態保存（選用）**：進度/徽章可用 `localStorage`，但**每次讀寫包 try/catch**，讀不到也要正常運作。
- **響應式＋觸控**：手機可用；互動點擊區夠大；拖曳一定同時支援點選。
- **無障礙基本**：色彩對比足夠、可鍵盤操作、按鈕有文字。
- **寫進 prompt**：「輸出單一自足 `.html`，CSS/JS 內嵌；外部只允許 Tailwind CDN ＋ Google Fonts，其餘資源內嵌（emoji/SVG/data URI）；原生 JS；顯示切換用 hidden；localStorage 需 try/catch；響應式且觸控友善（拖曳並存點選）。」

### 4.6 主控生成指令（可填模板）
```
你是這位教師的互動教材協作者。請為主題【主題】產出一份「單檔 HTML 互動學習頁」，

■ 引導軌跡（來自教學活動設計）：
【貼上起點→目標與要推進的引導步驟/操作子】

■ 年級與風格：年級【中/高】；風格 token 情緒【】‧主色【】‧強調色【】‧字體感【】‧圓角陰影【】。

■ 舉例池（只能用這些，不足標「待補」，禁止虛構通用例）：

■ 個人化生成器要吃的輸入與輸出模板：

■ 產出方式（務必兩段式）：
  第一段：先只輸出【區塊清單】：逐區「區塊名｜概念｜互動類型(1即時選擇題/2配對/3比喻演示/4個人化生成器/5進度徽章)｜完成訊號｜色彩」，一概念一區、≤【N】區；先不要寫 HTML，等我確認。
  第二段：我確認後，輸出**單一自足 .html**：

    - 文字精簡口語對小學生（標題≤14全形字、說明每段≤2行、禁長段落）。

    - 技術：CSS/JS 內嵌；框架＝Tailwind CDN＋Google Fonts；原生 JS；hidden 切換；localStorage 包 try/catch；響應式＋觸控（拖曳並存點選）。
    - 全份風格 token 一致。
```

## 5. 進階設計通則：把「能動的頁」做成「像老師的課」

> **這一節是精準化的核心。** 自動生成常止於「互動骨架對了」——能點、能拖、有回饋——但打開來像**能動卻空心的頁**：素材用 emoji 代替、例子是虛構通用、產物只是一句文字、視覺一體適用。老師手作的課差在七個地方；以下把每個落差寫成**可遷移的通則**（換主題照樣成立），重點是**為什麼**這樣設計。

### 5.1 真實素材呈現型錄（每種素材有固定呈現法，且用真實資料填）
> §4.5 說「素材務必嵌入、別用 emoji 靜默取代」是**鐵則**；這裡補**怎麼嵌**。關鍵心態：**素材不是配圖，素材本身就是教學內容。**

| 素材型別 | 呈現型 | 精準做法 |
|---|---|---|
| 操作截圖 / 實拍照 | **圖文交錯卡** | 加白框＋陰影的大圖，一張圖配一段說明，**左右交替**排（圖左文右 → 下一段圖右文左）造閱讀節奏；圈點關鍵處 |
| 影片 | **看情況：海報卡 或 內嵌** | **大型／長片（新聞、案例、需流量）→ 海報卡**：下載縮圖＋▶ 疊層＋一句「x:xx–x:xx 在講什麼」＋點卡連出原片（省流量、老師課堂播）。**短示範／操作片 → 直接 nocookie iframe 內嵌**，方便學生**反覆重播**跟著做。判準：**要學生自己反覆看＝內嵌；只是老師帶看一次的長片＝海報卡外連** |
| 網站 / 文章 | **預覽卡** 或 **真實任務導引** | 預覽卡＝favicon／og 縮圖＋標題＋開啟；或直接「帶學生去官方站自己操作」（給連結＋任務） |
| 結構化資料（門票 / 時間 / 地址 / 規格） | **標籤小格** | labeled chips 格狀排，**填真實數字**（例：全票70／半票35、10:00–17:10、安平區國勝路82號） |

- **佈局通則**：圖一塊、文一塊、**左右交替**；每張圖都是**內容**、不是裝飾。
- **設計邏輯**：真實素材＝這堂課在教「真的東西」的證據；用 emoji 佔位＝把真實感抽掉，內容當場空心。

### 5.2 具體性原則：真實、在地、可查證（殺掉通用佔位例）
- **通則**：任務、例子、數據一律用**真實且在地的具體事物**（真地名、真數字、真連結），不用虛構的通用例。
- **檢驗一句話**：**「學生能不能真的照著去做、或查得到？」** 能 → 具體夠了；不能 → 還是佔位例，重寫。
- **對照**〔例，換主題重推〕：「找出 3 個**東區**景點」「**水交社**週六幾點開」＞「找一些景點」；真「全票70／半票35」＞「門票 XX 元」。
- **設計邏輯**：具體＝可操作＝有真實感；學生知道自己在學一件**真的事**，而不是做練習題。

### 5.3 個人化產物要「看得見、帶得走」
- **通則**：G7 擁有感的產物**不是一句回饋，而是一個學生可帶走的成品**——一張卡、一份表、一張圖。
- **精準做法**：輸入 → 套模板 → 螢幕上先長出成品（文字卡）→ 提供**匯出**：`canvas` 畫成 PNG 下載（標題條＋內容行＋頁尾署名），同時給「一鍵複製文字」當退路。
- **佈署提醒**：公開 Artifact 平台可能擋下載 → 該情境改以「複製」或引導截圖（呼應 §4.5 情境 A/B）。
- **設計邏輯**：帶得走＝真的屬於他＝願意投入、還能秀給別人（G9 展示的種子）。

### 5.4 承重比喻要緊接「預測測驗」
- **通則**：每個具象化比喻（G3）後面**緊接一個用該比喻能預測的小測驗**，驗證學生**真的接住**了比喻，而非聽過就算。
- 〔例〕「主題像速食店**套餐**」→ 立刻問「**自然風景套餐**你會選哪些景點？」（多選＋解釋為什麼對／錯）。
- **設計邏輯**：比喻的價值在能**遷移去預測**；不接一個測驗，就不知道遷移到底發生了沒。

### 5.5 年級視覺分級（可調參數，同一套邏輯換一層皮）
| 參數 | 中年級（3–4） | 高年級（5–6） |
|---|---|---|
| 基礎字級／行高 | **18px＋／1.7**，大按鈕、多留白 | 稍小、密度可高一點 |
| 情緒與色 | 暖色（奶油底＋暖橘）、圓潤可愛 | 冷色／科技感（可深色） |
| 一頁份量 | 少一點、步子更小 | 可多放機制（進度、徽章、跨裝置同步） |
- **設計邏輯**：字級與情緒色就是**認知負荷與親和度的旋鈕**；互動邏輯不變，只調這層皮。

### 5.6 情感入口與交出前自檢（讓每個學生上得了車、也交得出來）
- **入口（低風險暖身）**：開場放一個**人人能答、沒有錯答案**的問題（「你有沒有…?」），依回答給**不同鼓勵**（分支）——先讓每個學生都上車。
- **出口（自檢清單）**：個人化產出前放一個**勾選清單**，把通關條件變成學生自己勾的項目（G8 界線落地）。
- **設計邏輯**：入口降門檻、出口給界線，中間才敢放挑戰；三者是一組，缺一個學生就掉隊或交不出來。

### 5.7 進度里程碑要「有意義」
- **通則**：進度／徽章綁**完成一個真任務**（做出調查表、產出構想卡、填滿 N 格），**不是每次點擊都 +1**。
- **設計邏輯**：里程碑是「真的跨過一步」的證據，才有成就感、也才不會灌水。

> **一句話收束**：互動樣式庫（§3）給的是**能動**；這一節給的是**像課**——真實素材做內容、在地具體任務、可帶走產物、比喻接測驗、年級分級、情感入口出口、里程碑有意義。**換任何主題，這七條都成立。**

## 7. 生成後自檢（用提問）

**精準通則（§5）的自檢——最容易漏，優先看：**
- **素材**：S7 採用的每張圖／影片／連結，都用 §5.1 的呈現型（圖文交錯卡／海報卡／預覽卡／標籤小格）**實際嵌入**了嗎？還是被 emoji／純文字悄悄取代？
- **具體**：任務與例子是**真實在地、查得到**的嗎（真地名／真數字／真連結）？還是虛構通用佔位例？（用「學生能不能真的去做／查到」檢驗）
- **產物**：個人化生成器有讓學生做出**可帶走的成品**（可下載圖／可複製卡），而不只是一句回饋嗎？
- **比喻**：每個承重比喻後面**接了一個預測測驗**嗎？
- **分級**：字級、情緒色、一頁份量對到年級了嗎（中年級大而暖、少而慢）？
- **入口出口**：有低風險暖身讓人人上車、有交出前自檢清單嗎？進度里程碑綁的是**真任務**還是每次點擊？

**基本盤：**
- 每個概念區塊是不是**至少有一個要動手的互動**？還是又變成只能讀？
- 作答/操作後**有沒有即時回饋**（對錯 ＋ 為什麼）？
- 有沒有一個**個人化生成器**，讓學生做出**屬於自己的**東西？
- 區塊順序＝引導軌跡順序嗎？一概念一色區嗎？
- 文字夠短、夠口語、對小學生嗎？
- 是**單一自足 .html** 嗎？打開就能動、手機能用、拖曳也能點選嗎？
- **★ 素材對帳：S7 採用的每一項視覺素材（照片、地圖、連結）都真的出現在成品了嗎？** 還是被 emoji 靜默取代了？未取得的有沒有用「待補：編號」佔位框標出來？
- 佈署情境對嗎？課堂本機檔就該用外部照片/地圖/連結把內容做厚（斷網有退回）；公開發布才全內嵌。
- 風格 token 整份一致嗎？年級主題對嗎？
- 涉及 AI／公開時，界線（查核/隱私）在頁面上出現了嗎（G8）？
- 換一個主題，這套**區塊清單＋生成指令**還走得通嗎？
