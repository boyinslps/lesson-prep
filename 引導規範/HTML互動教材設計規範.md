# HTML 互動教材設計規範（把引導軌跡變成「可動手」的學習頁 × 精確 AI 生成控制）

> 這份文件寫的是**過程的邏輯**與**如何精確驅動 AI 產出一頁 HTML 互動教材**，不是某主題的模板。
> 目標：拿到任何主題的引導軌跡，能生成一份**學生自己打開就能操作、有即時回饋、能個人化**的單檔 HTML 學習材料。
>
> **使用原則**
> - 例子一律標「〔例，換主題請重推〕」。
> - 先讀 `教學活動設計規範.md`（引導軌跡與操作子 G1–G9）與 `簡報設計規範.md`（兩段式生成、五軸控制的手法）。本規範是它們的「互動版延伸」。
> - 原型參考：`../分析資料/四年級簡報/Scratch.html`（老師手作的互動教材），拆解見 `../教學風格分析.md` U4-★。

## 1. 核心：HTML 教材 ＝ 把引導軌跡「可操作化」

簡報是把軌跡外顯成**一頁一步讓學生看**；HTML 教材再進一步——把每一步變成**學生自己動手做、系統立刻回饋**的互動。

**簡報 → HTML 的關鍵躍遷：`被動看` → `主動做 + 即時知道對不對`。**

這帶來三個只有 HTML 能給的槓桿（也是選擇做 HTML 而非簡報的理由）：
1. **即時回饋迴圈**：學生一操作，頁面馬上告訴他對／錯／為什麼——把 G6「預測—驗證」變成秒級循環。
2. **做中學**：能拖、能點、能試的東西，不用只用讀的（強化 G4）。
3. **個人化產物**：學生輸入自己的資料，頁面**當場生出屬於他的成果**（強化 G7 擁有感）。

> 判斷「這個主題該做 HTML 而非簡報」的標準：**它有沒有值得學生反覆試、需要即時回饋、或能個人化的環節？** 有 → 適合 HTML。純線性講述 → 簡報就夠。

## 2. 從引導軌跡投影成互動區塊

把操作子（G1–G9）投影成**互動區塊型**。與簡報不同的是：每個概念區塊盡量帶「一個要學生動手的動作」與「一個完成訊號」。

| 引導操作子 | 互動區塊型 | 學生在這區要「做」什麼 | 即時回饋 |
|---|---|---|---|
| G1 製造勢能差 | **情境開場區** | 看對比／點一下切換「問題 vs 理想」 | — |
| G3 具象化抽象 | **比喻演示區** | 操作一個可玩的比喻（拖、點、滑）看概念怎麼動 | 畫面即時反應 |
| G6 預測—驗證 | **即時選擇題區** | 先選答案 | 立刻顯示對/錯 ＋ **為什麼** |
| G4 降低門檻 | **拖曳配對／填空／選單區** | 把積木/步驟拖進正確插槽、或從選單挑 | 對→鎖定並前進；錯→提示再試 |
| G5 通關條件 | **進度／徽章區** | 完成小關解鎖徽章 | 進度條、徽章亮起 |
| G7 在地個人化 | **個人化生成器區** | 填自己的資料（名稱/內容…） | 當場產出**屬於他的**成果／預覽 |
| G8 給界線 | **查核／隱私提示區** | 勾選「可公開 vs 要隱藏」 | 標出紅燈項目 |
| G9 產出展示 | **匯出／分享區** | 複製成果、下載、或秀出來 | 一鍵複製成功提示 |

**版面組織原則（延續原型）**：**一個概念一個色區**（藍/橘/綠/紫…各一色），色彩幫學生分辨「現在在學哪一塊」；由上而下就是引導軌跡的順序。

## 3. 互動樣式庫（可重用的五種互動，AI 照這幾種做就穩）

不要讓 AI 每次自由發明互動。**收斂成這幾種可靠、好生成、好操作的互動**，換主題只換內容：

1. **即時選擇題**：一題 + 選項；點選後立刻變色顯示對/錯，並秀一句「為什麼」。（承 G6）
2. **拖曳/點選配對**：把卡片（積木、步驟、詞）拖進正確插槽；全對才解鎖下一區。行動裝置用「點卡→點槽」取代拖曳較穩。（承 G4）
3. **可玩的比喻演示**：一個小舞台，拖滑桿/點按鈕，即時看到概念行為（如拖物件看座標數字變、按一下看「變數盒子」數字被覆寫）。（承 G3）
4. **個人化生成器**：幾個輸入框 → 按鈕 → 依模板即時組出學生自己的成果文字/預覽（如把他填的景點資料組成導覽台詞）。（承 G7）
5. **進度徽章**：完成各區點亮徽章＋進度條；全通關給一個完成畫面。（承 G5）

> 每個知識點**至少配一個「做」的互動**（1 或 2 或 3 擇一），不要整頁只有讀。

## 4. ★ 精確 AI 生成控制系統（HTML 版五軸）

沿用簡報規範的手法：**兩段式生成 ＋ 五軸夾住**。HTML 版的五軸是：**結構／互動／文字／風格／技術**。

### 4.0 兩段式生成（總開關）
1. **第一段——先產「區塊清單」（manifest）**：只輸出一張表，逐區列
   `{區塊 · 對應概念 · 互動類型(§3的1–5) · 完成訊號 · 色彩}`，一概念一區塊。**你審核、增刪、調序。**
2. **第二段——生成單檔 HTML**：清單定案後，才產出完整 `.html`，不准自行增加區塊或互動。

### 4.1 結構控制軸
- **原則**：一個概念一個色區；由上而下＝引導軌跡順序；頁首一句話說明「這頁要帶你做到什麼」，頁尾是個人化生成器＋匯出。**中年級**區塊一多（≥ 4 個或超過約 3 個手機螢幕）就拆成步驟分頁，見 §5.8；**高年級**一個環節一步（步驟分頁）＋老師分段公布，見 §5.10。
- **寫進 prompt**：「先只輸出**區塊清單**：逐區列【區塊名｜概念｜互動類型(1–5)｜完成訊號｜色彩】，一概念一區、區塊數 ≤`N`；先不要寫 HTML，等我確認。」

### 4.2 互動控制軸
- **原則**：每個知識點至少一個 §3 的互動；**即時回饋**是必要件（選了/拖了要馬上知道對錯與為什麼）；行動裝置友善（點選優先於拖曳）。
- **寫進 prompt**：「每個概念區塊必含一個 §3 互動（即時選擇題／配對／比喻演示 擇一），作答後**立即**顯示對錯與一句原因；配對全對才解鎖下一區；用點選相容觸控。**不要只有文字說明。**」

### 4.3 文字控制軸（同簡報精神：頁面是提示不是課本）
- **原則**：短、口語、指令式；對小學生說話。
- **中年級（3–4）更嚴格：只留關鍵字或提問**，細則與檢驗見 **§5.9**（2026-10-02 教師定案）。
- **可調參數（預設，越低年級越少）**：區塊標題 ≤ **全形 14 字**；每段說明 ≤ **2 行**；按鈕/選項字 ≤ **8 字**；回饋訊息一句話。
- **寫進 prompt**：「文字精簡口語，對小學生；標題 ≤14 全形字；說明每段 ≤2 行；**禁止長段落與課本式敘述**；用『你、我們』與鼓勵語氣。」

### 4.4 風格控制軸
- **原則**：用**風格 token**（同簡報 §3）決定整體視覺；**單檔內一致**；依年級調主題（中年級明亮圓潤／高年級酷炫科幻）。
- **寫進 prompt**：「風格 token：情緒【】、主色系【】、強調色【】、字體感【圓潤可愛/俐落科技】、圓角與陰影【多/少】。整份一致；每個概念一個色區但同一套風格語言。」

### 4.5 技術控制軸（讓 AI 產出「打開就能動」的單檔）
> 這一軸最容易被忽略，卻決定生成品質。**明確規定技術邊界，AI 才不會產出跑不動或依賴外部資源的檔案。**

#### ★ 先決定佈署情境（這決定外部資源能不能用，別搞錯）
> **教訓**：曾把「Artifact 平台不能外連圖」的限制誤套到本機課堂檔上，結果 S7 清單裡的照片、地圖、外部連結全被 emoji 悄悄取代，內容空洞撐不起一節課。**兩種情境的規則相反，動筆前先確認是哪一種。**

- **A. 課堂本機檔（預設）**：用瀏覽器在教室電腦雙擊開啟，**沒有 CSP 限制**。→ **可、且應**使用外部資源把內容做厚：真實景點**照片**、**地圖 iframe**（如 Google 地圖 `...&output=embed`）、**外部網站連結**（如官方旅遊網）。唯一要求：**主結構與互動不因斷網而壞**——外部圖載不出時要有替代文字或 emoji 佔位（`onerror` 退回）。
- **B. 公開發布 / Artifact 平台**：受 CSP 限制，外部資源會被擋。→ 此時才回到「全內嵌」：圖片用 emoji／內嵌 SVG／data URI，外部照片換成開放授權或內嵌版。

**鐵則（兩情境都適用）**：**S7 清單裡採用的視覺素材（照片、地圖、連結）必須實際出現在成品**，不得用 emoji 靜默取代。某素材若尚未取得，用**明確佔位框**標「待補：素材編號」，而不是省略。

- **單一自足檔**：輸出**一個 `.html`**，CSS/JS 全部**內嵌**；不依賴任何**本地**檔或建置流程（外部 CDN／圖床／地圖依佈署情境而定）。
- **字型與框架**：Tailwind CDN（`https://cdn.tailwindcss.com`）＋ 一組 Google Fonts（圓體如 Fredoka／Noto Sans TC）。
- **純前端**：原生 JS，不用框架建置；顯示切換用 `hidden` 屬性或 class，不要重繪整頁。
- **狀態保存（選用）**：進度/徽章可用 `localStorage`，但**每次讀寫包 try/catch**，讀不到也要正常運作。
- **響應式＋觸控**：手機可用；互動點擊區夠大；拖曳一定同時支援點選。
- **無障礙基本**：色彩對比足夠、可鍵盤操作、按鈕有文字。
- **寫進 prompt**：「輸出單一自足 `.html`，CSS/JS 內嵌；外部只允許 Tailwind CDN ＋ Google Fonts，其餘資源內嵌（emoji/SVG/data URI）；原生 JS；顯示切換用 hidden；localStorage 需 try/catch；響應式且觸控友善（拖曳並存點選）。」

### 4.6 主控生成指令（可填模板）
```
你是這位教師的互動教材協作者。請為主題【主題】產出一份「單檔 HTML 互動學習頁」，
把一段引導軌跡變成「學生自己動手做、即時回饋、可個人化」的頁面。

■ 引導軌跡（來自教學活動設計）：
【貼上起點→目標與要推進的引導步驟/操作子】

■ 年級與風格：年級【中/高】；風格 token 情緒【】‧主色【】‧強調色【】‧字體感【】‧圓角陰影【】。

■ 舉例池（只能用這些，不足標「待補」，禁止虛構通用例）：
【在地／個人真實例子】

■ 個人化生成器要吃的輸入與輸出模板：
【輸入欄位：… ；輸出把它們組成：…（學生自己的成果）】

■ 產出方式（務必兩段式）：
  第一段：先只輸出【區塊清單】：逐區「區塊名｜概念｜互動類型(1即時選擇題/2配對/3比喻演示/4個人化生成器/5進度徽章)｜完成訊號｜色彩」，一概念一區、≤【N】區；先不要寫 HTML，等我確認。
  第二段：我確認後，輸出**單一自足 .html**：
    - 每概念一色區、由上而下依軌跡順序；每區至少一個互動且作答後立即回饋對錯＋一句原因；配對全對才解鎖下一區。
    - 文字精簡口語對小學生（標題≤14全形字、說明每段≤2行、禁長段落）。
    - 佈署情境＝【A 課堂本機檔／B 公開Artifact】。A：可用外部照片/地圖iframe/連結，**S7 採用的視覺素材務必實際嵌入**（斷網以 onerror 退回佔位）；B：全內嵌、圖片用 emoji/SVG/data URI。
    - 技術：CSS/JS 內嵌；框架＝Tailwind CDN＋Google Fonts；原生 JS；hidden 切換；localStorage 包 try/catch；響應式＋觸控（拖曳並存點選）。
    - 全份風格 token 一致。
    - 頁面版型依年級：
      中年級＝區塊 ≥【4】或預估超過 3 個手機螢幕，改成步驟分頁（§5.8）：頂端固定進度列、每步上一步／下一步、hidden 切換保留作答、繳交與完成獎勵放最後一步。
      高年級＝一個環節一步的步驟分頁（§5.8、§5.10）：圖片可點開放大（滾輪縮放）、每環節一張大色卡、答案與解析等老師分段公布、開場留老師的影片欄位（不做一鍵表態題）、環節聚焦本節主技能。
    - 有繳交的學習單：依《學習單資料與提交規範》§2-e 內嵌 `<script type="application/json" id="grading-spec">`——
      開放題題幹＋評分方式＋標準＋配分，加上 `scoring`（100 分、80 起跳、20 分依題數平均分給主要題，加分題另外加）。
```

## 5. 進階設計通則：把「能動的頁」做成「像老師的課」

> **這一節是精準化的核心。** 自動生成常止於「互動骨架對了」——能點、能拖、有回饋——但打開來像**能動卻空心的頁**：素材用 emoji 代替、例子是虛構通用、產物只是一句文字、視覺一體適用。老師手作的課差在七個地方；以下把每個落差寫成**可遷移的通則**（換主題照樣成立），重點是**為什麼**這樣設計。

### 5.1 真實素材呈現型錄（每種素材有固定呈現法，且用真實資料填）
> §4.5 說「素材務必嵌入、別用 emoji 靜默取代」是**鐵則**；這裡補**怎麼嵌**。關鍵心態：**素材不是配圖，素材本身就是教學內容。**

| 素材型別 | 呈現型 | 精準做法 |
|---|---|---|
| 操作截圖 / 實拍照 | **圖文交錯卡** | 加白框＋陰影的大圖，一張圖配一段說明，**左右交替**排（圖左文右 → 下一段圖右文左）造閱讀節奏；圈點關鍵處 |
| 影片 | **看情況：海報卡 或 內嵌** | **大型／長片（新聞、案例、需流量）→ 海報卡**：下載縮圖＋▶ 疊層＋一句「x:xx–x:xx 在講什麼」＋點卡連出原片（省流量、老師課堂播）。**短示範／操作片 → 直接 nocookie iframe 內嵌**，方便學生**反覆重播**跟著做。判準：**要學生自己反覆看＝內嵌；只是老師帶看一次的長片＝海報卡外連** |
| 網站 / 文章 | **預覽卡** 或 **真實任務導引** | 預覽卡＝favicon／og 縮圖＋標題＋開啟；或直接「帶學生去官方站自己操作」（給連結＋任務） |
| 結構化資料（門票 / 時間 / 地址 / 規格） | **標籤小格** | labeled chips 格狀排，**填真實數字**（例：全票70／半票35、10:00–17:10、安平區國勝路82號） |

- **佈局通則**：圖一塊、文一塊、**左右交替**；每張圖都是**內容**、不是裝飾。
- **設計邏輯**：真實素材＝這堂課在教「真的東西」的證據；用 emoji 佔位＝把真實感抽掉，內容當場空心。

### 5.2 具體性原則：真實、在地、可查證（殺掉通用佔位例）
- **通則**：任務、例子、數據一律用**真實且在地的具體事物**（真地名、真數字、真連結），不用虛構的通用例。
- **檢驗一句話**：**「學生能不能真的照著去做、或查得到？」** 能 → 具體夠了；不能 → 還是佔位例，重寫。
- **對照**〔例，換主題重推〕：「找出 3 個**東區**景點」「**水交社**週六幾點開」＞「找一些景點」；真「全票70／半票35」＞「門票 XX 元」。
- **設計邏輯**：具體＝可操作＝有真實感；學生知道自己在學一件**真的事**，而不是做練習題。

### 5.3 個人化產物要「看得見、帶得走」
- **通則**：G7 擁有感的產物**不是一句回饋，而是一個學生可帶走的成品**——一張卡、一份表、一張圖。
- **精準做法**：輸入 → 套模板 → 螢幕上先長出成品（文字卡）→ 提供**匯出**：`canvas` 畫成 PNG 下載（標題條＋內容行＋頁尾署名），同時給「一鍵複製文字」當退路。
- **佈署提醒**：公開 Artifact 平台可能擋下載 → 該情境改以「複製」或引導截圖（呼應 §4.5 情境 A/B）。
- **設計邏輯**：帶得走＝真的屬於他＝願意投入、還能秀給別人（G9 展示的種子）。

### 5.4 承重比喻要緊接「預測測驗」
- **通則**：每個具象化比喻（G3）後面**緊接一個用該比喻能預測的小測驗**，驗證學生**真的接住**了比喻，而非聽過就算。
- 〔例〕「主題像速食店**套餐**」→ 立刻問「**自然風景套餐**你會選哪些景點？」（多選＋解釋為什麼對／錯）。
- **設計邏輯**：比喻的價值在能**遷移去預測**；不接一個測驗，就不知道遷移到底發生了沒。

### 5.5 年級分級：不只換皮，連「頁面的概念」都不同（2026-10-02 教師修正）
| 參數 | 中年級（3–4） | 高年級（5–6） |
|---|---|---|
| 基礎字級／行高 | **18px＋／1.7**，大按鈕、多留白 | 稍小、密度可高一點 |
| 情緒與色 | 暖色（奶油底＋暖橘）、圓潤可愛 | 冷色（淺灰藍底＋靛藍／天藍），卡片色區分環節 |
| **頁面概念** | **學生自學的步驟頁**：學習路徑分頁（§5.8） | **老師帶課的教學活動頁**：一個環節一步的步驟分頁＋老師分段公布（§5.8、§5.10） |
| **文字** | 關鍵字＋提問（§5.9） | 完整句子說明概念，附〔例〕與「發現了嗎？」的歸納 |
| **互動深度** | 點一下、選一個、填一格 | 判斷＋**說出證據**、分類、比較、動手查證 |
| 一頁份量 | 少一點、步子更小 | 環節多、每環節有示範與練習，可放全班投票、留言牆、跨裝置同步 |
- **設計邏輯**：字級與情緒色是**認知負荷與親和度的旋鈕**；但高年級要的不只是換皮——**頁面的角色、文字量、互動要求的思考層次都要跟著升級**。把中年級的版型（分步驟、只留關鍵字、單選表態）套到高年級，學生會覺得幼稚、也練不到推理（五上 L04 第一版踩過）。

### 5.6 情感入口與交出前自檢（讓每個學生上得了車、也交得出來）
- **入口（低風險暖身）**：開場放一個**人人能答、沒有錯答案**的問題（「你有沒有…?」），依回答給**不同鼓勵**（分支）——先讓每個學生都上車。
- **出口（自檢清單）**：個人化產出前放一個**勾選清單**，把通關條件變成學生自己勾的項目（G8 界線落地）。
- **設計邏輯**：入口降門檻、出口給界線，中間才敢放挑戰；三者是一組，缺一個學生就掉隊或交不出來。

### 5.7 進度里程碑要「有意義」
- **通則**：進度／徽章綁**完成一個真任務**（做出調查表、產出構想卡、填滿 N 格），**不是每次點擊都 +1**。
- **設計邏輯**：里程碑是「真的跨過一步」的證據，才有成就感、也才不會灌水。

### 5.8 頁面份量與導覽：長頁拆成「學習路徑」步驟（2026-09-30 教師採納，四上 L03 首例）
> **適用範圍：中、高年級都用（2026-10-05 起）。** 原本只給中年級；五上 L04 教師要求「依樣仿造四年級的步驟切換頁面，這樣更清楚」，高年級也改用步驟分頁，但內容、文字、互動深度仍照 §5.10（一步＝一個環節，老師分段公布照舊）。
- **起因**：區塊一多，單頁由上往下捲會非常長。小學生找不到自己在哪、做完不知道下一步做什麼，手機上尤其明顯。
- **什麼時候要拆**：區塊 **≥ 4 個**，或預估頁高超過**手機寬度下約 3 個螢幕**。區塊少、一兩屏看得完的頁面**不必為拆而拆**。
- **通則**：
  1. **一步＝引導軌跡的一個階段**（含 1～2 個相關區塊、一個主要動作）。步驟順序就是軌跡順序（起點 → … → 產出 → 交出）。每步大約 **1～1.5 個桌面螢幕**；哪幾個區塊併成一步，看它們是不是同一個動作，**換主題請重推**，不要照抄下面的示範切法。
  2. **頂端固定進度列**：圓點＋短名稱（≤ 4 字）；圓點**可點擊跳步**，預設**不鎖定**（除非後一步真的要用到前一步的產物）。手機寬度只留圓點＋一行「第 n 步／共 N 步 · 名稱」，**不可橫向捲動**——步驟超過 8 個時合併步驟，而不是縮小圓點。
  3. **每步底部有「← 上一步」「下一步：〈下一步名稱〉→」**；第一步沒有上一步、最後一步沒有下一步。
  4. **完成標記綁真任務**（呼應 §5.7）：有互動題的步驟，題目做完才畫綠色 ✓；純閱讀步驟走過就算。當前步驟用主色標示，不畫 ✓。
  5. **切步不丟狀態**：只用 `hidden` 切換顯示，不重建 DOM；所有作答、拖曳結果、輸入值都保留；切步後捲回頁面頂端。
  6. **固定的只有進度列**：識別列（《學習單資料與提交規範》§1）仍在頁面最上方，但**不固定**——手機上兩條都固定會吃掉約六分之一畫面。
  7. **「交出」放最後一步**：產出物（構想卡等）在倒數第二步；最後一步放「帶走它」的教學、繳交按鈕與完成獎勵區（《學習單資料與提交規範》§3-b）。繳交前的確認對話框要回報**各步**的完成狀況，因為學生可能有步驟沒走到。
  8. **靜態說明頁（如給老師課堂帶討論的比較表）**不必為它硬做互動，但仍佔一步，放在軌跡需要它的位置。
  9. **無障礙**：圓點是真的 `<button>`，當前步驟加 `aria-current="step"`，每顆有 `aria-label`（「第 n 步：名稱」）。
- **示範（換主題請重推）**：四上 L03「規劃行程，從哪裡開始？」原本七個區塊排成一長頁，改成「起點 → 主題 → 分類 → 比較 → 同行 → 宣言 → 交出」7 步；桌面每步約 800～1150px。步驟名稱直接沿用學生在軌跡上要做的事，學生一看進度列就知道「還剩什麼」。
- **設計邏輯**：**一次只給一個任務**降低認知負荷；把學習路徑**外顯**（我在第幾步、還剩幾步），學生才有掌控感；每步有明確完成訊號，才走得下去。
- **寫進 prompt**：「區塊 ≥ 4 或預估超過 3 個手機螢幕時，改成步驟分頁：頂端固定進度列（圓點可點跳步、手機只留圓點＋一行文字、不可橫向捲動）；每步底部有上一步／下一步；用 hidden 切換並保留作答狀態，切步後捲回頂端；一步約 1～1.5 個螢幕；完成 ✓ 綁真任務；繳交與完成獎勵放最後一步；識別列不固定。」

### 5.9 文字要精簡：給中年級「關鍵字＋提問」，不是說明文（2026-10-02 教師定案，四上 L04 首例）
- **起因**：L04 第一版把原因、例外、注意事項都寫成完整句子，一個區塊三、四行字。對四年級學生來說，網頁上超過一兩行的字，**幾乎不會讀**，只會直接找按鈕。
- **通則**：
  1. **每個區塊只留「關鍵字」或「一個提問」**。說明用**詞組＋符號**（`走路 → 排很多站`、`同一區・混著挑`），不用長句。
  2. **一句只講一件事、盡量不超過 15 個字**；一個卡片正文最多 2～3 行。需要更多解釋？交給**老師口頭講**或**圖／範例**，不寫在頁面上。
  3. **結論用「💡」一句話**收尾（例：「💡 只有 4 站，卻玩了一整天！」），不要寫成段落。
  4. **操作步驟 ＝ 動詞開頭的短句**（「選字，Ctrl＋C」「切回文件」），一步一行，快捷鍵用 `<kbd>`。
  5. **多用圖、少用字**：能用截圖、照片、時間軸、標籤小格說清楚的，就不寫字。
  6. **補充說明（例外、備案、為什麼）刪掉或縮成一行小字**；真的要保留，放在「點開才看」或老師講解。
  7. **出處、授權標示**維持，但用最小字級單行帶過，不佔版面。
  8. **提示訊息**（成功／失敗／空白提醒）也一樣短：≤ 15 個字，說「現在要做什麼」，不說原因。
- **檢驗一句話**：**把頁面念給四年級學生聽，他聽到一半會不會分心？** 會 → 還是太多字，繼續刪。
- **適用範圍：中年級（3–4）。** 高年級的文字原則不同，見 §5.10 第 3 點。
- **設計邏輯**：中年級閱讀速度與耐心有限，讀字會**吃掉實作時間**（呼應 §5.8 的份量原則）；關鍵字讓學生一眼抓到要做什麼，提問讓學生**主動想**而不是被動讀。
- **寫進 prompt**：「文字精簡給中年級：每個區塊只留關鍵字或一個提問；一句不超過 15 字、一張卡片正文不超過 3 行；用詞組＋符號（→、・、💡）取代長句；操作步驟用動詞開頭短句；能用圖就不用字；例外與補充說明刪掉或交給老師口述；提示訊息也要短。」

### 5.10 高年級（5–6）的編排：老師帶課的教學活動頁（2026-10-02 教師定案，依五上 L01～L03 歸納、五上 L04 首例）
- **起因**：五上 L04 第一版照中年級的做法（分步驟、只留關鍵字、開場問「你會轉傳嗎？會／不會／不確定」），教師指出「概念和四年級不一樣」「這也太簡單了，不適合高年級」。回頭看五上 L01～L03，高年級的頁面是**老師投影帶課、學生同步操作**的教學活動頁，不是學生自己一步步走完的自學頁。
- **通則**：
  1. **一個環節一步（2026-10-05 改，五上 L04）**：頁首放標題、「X年級上學期 · L## 主題 · 教學活動流程（40 分鐘）」。環節照 §5.8 做成**步驟分頁**：頂端固定進度列（圓點＋≤ 4 字名稱，例：開場影片／認識農場／以圖搜圖／查證網站／截圖搜尋／我的步驟），每步底部上一步／下一步，識別列在最上方但不固定，繳交與獎勵放最後一步。每個環節仍是 `border-4` 大色卡。（五上 L01～L03 是舊版單頁長捲，不回頭改。）
     - **圖片一律可點開放大**：`img.shotimg` 點一下開燈箱，滾輪多段縮放、放大後拖曳移動、雙擊還原、Esc 關閉（做法同競賽專區 C03）。
     - **沒填身分按繳交，不要捲回頂端**：在繳交鈕下方顯示提示，並把空著的年級／班級／座號框標紅。
  2. **老師掌控節奏：分段公布**：答案、解析、全班統計放在 `data-r` 區塊，旁邊顯示「🔒 等老師公布」。公布鈕放在各環節標題旁（《學習單資料與提交規範》§5-8），全班畫面同步揭曉。這樣學生先獨立判斷，老師再帶全班討論。
  3. **文字是「說明」不是「關鍵字」**：用完整句子講清楚概念，可以有兩三行的段落；常用句型——「還記得 L03 的…嗎？」（接舊）、「〔例〕…」（舉例）、「💡 發現了嗎？…」（歸納）、「🤔 想一想：…」（留給全班討論的提問）。仍然不寫成課本，**每段都要有存在的理由**。
  4. **互動要練到推理，不是表態**：
     - **開場**：教師常用自己挑的短影片引起動機 → **預設留一個開場影片欄位**（填網址就嵌入）＋一句「🤔 想一想」提問即可，不要替老師設計開場題。**絕對不要**做「你會不會／你覺得呢」這種一鍵表態題（五上 L04 被退件）。真的需要開場題時，才做多案例判斷＋勾出線索。
     - 其他常用型：分類（把句子／標題切段標成兩類）、比較（兩份資料比可信度）、評分（星等＋理由）、動手查證（用工具查出答案再作答，附證據網址）。
  5. **前後課要接起來**：高年級同一學期是一條能力線（例：五上 L01 目的 → L02 事實與意見 → L03 身分證與 5W → L04 整合用在短影音）。每節至少有一處**明確點名前一課的工具**並拿來用，最後的「今天你帶走的能力」要預告下一課。
  6. **示範 → 練習成對**：每個新工具先放「👩‍🏫 老師示範」卡（結果收在 `<details>` 裡，老師現場展開），緊接一張「✋ 換你查」卡，用**另一個**真實案例讓學生自己做。由淺到深排（例：照片以圖搜圖 → 影片截圖＋關鍵字）。
  7. **真實素材要做厚**：圖片用查核報告裡的網傳擷圖與查核圖卡（標出處），影片直接嵌 YouTube（原始新聞、被搬運的農場片都可以，當教材看），延伸閱讀做成虛線框連結卡。
  8. **聚焦一個主技能，其餘刪掉**：先問「這節課的重點是什麼？」（例：五上 L04＝圖片反向搜尋＋查證網站），所有環節都要服務它；概念說明環節只講清楚「是什麼、怎麼認」，不另外加分類、拆解等小練習。全班投票分布、留言牆**預設不做**，教師要求才加。
  9. **收束卡**：「🎖️ 今天你帶走的能力」＋一句能力命名＋下一課預告，再接延伸連結卡、繳交、完成獎勵。
- **檢驗一句話**：**把頁面投影出來，老師能不能照著一路帶完一節課，而且每個環節學生都得「給證據」才能作答？** 不能 → 還是中年級的自學頁思維，重做。
- **設計邏輯**：高年級的認知能力已經可以處理多案例比較與證據推理；頁面如果只要求點一下，等於浪費了這個年紀最該練的能力。老師分段公布則讓「先獨立想 → 再全班對答案討論」這個節奏成立，也避免學生直接看答案。
- **範本**：五上 L01（8 則真假投票＋老師公布＋危害推論短文）、L02（比喻卡＋分類投票＋文章畫線）、L03（A/B 網站比較＋5W 翻卡＋三網站評分站＋配對）、L04（開場影片欄位＋農場文與 AI 假資訊影片說明＋照片以圖搜圖示範＋查證網站兩種用法練習＋影片截圖加關鍵字示範與練習＋查證步驟開放題）。**換主題請重推**，看的是編排邏輯，不是照抄版面。
- **寫進 prompt**：「高年級版：一個環節一步的步驟分頁（頂端固定進度列、每步上一步／下一步、繳交放最後一步）；圖片點開放大可滾輪縮放；沒填身分按繳交不捲回頂端，只在按鈕下提示並標紅空格；每環節一張大色卡；答案與解析放進老師分段公布區塊（🔒 等老師公布）；文字用完整句子說明，並用『還記得…』『〔例〕』『💡 發現了嗎』『🤔 想一想』；開場留老師的影片欄位，不做一鍵表態題；全部環節聚焦本節主技能，不加投票分布與留言牆；每個新工具先老師示範再學生用另一個案例練習；至少一處點名前一課的工具；結尾放『今天你帶走的能力』＋下一課預告。」

> **一句話收束**：互動樣式庫（§3）給的是**能動**；這一節給的是**像課**——真實素材做內容、在地具體任務、可帶走產物、比喻接測驗、年級分級、情感入口出口、里程碑有意義、中年級拆成看得見的學習路徑並精簡成關鍵字與提問、高年級做成老師帶課的教學活動頁並要求給證據。**換任何主題，這十條都成立。**

## 6. Few-shot 示範

### 示範：主題「用 Google 試算表管理班費」（中年級、混合互動）

## 7. 生成後自檢（用提問）

**精準通則（§5）的自檢——最容易漏，優先看：**
- **素材**：S7 採用的每張圖／影片／連結，都用 §5.1 的呈現型（圖文交錯卡／海報卡／預覽卡／標籤小格）**實際嵌入**了嗎？還是被 emoji／純文字悄悄取代？
- **具體**：任務與例子是**真實在地、查得到**的嗎（真地名／真數字／真連結）？還是虛構通用佔位例？（用「學生能不能真的去做／查到」檢驗）
- **產物**：個人化生成器有讓學生做出**可帶走的成品**（可下載圖／可複製卡），而不只是一句回饋嗎？
- **比喻**：每個承重比喻後面**接了一個預測測驗**嗎？
- **分級**：字級、情緒色、一頁份量對到年級了嗎（中年級大而暖、少而慢）？
- **入口出口**：有低風險暖身讓人人上車、有交出前自檢清單嗎？進度里程碑綁的是**真任務**還是每次點擊？

**基本盤：**
- **先確認年級版型（§5.5）**：中年級是學生自學的步驟頁、高年級是老師帶課的教學活動頁，有沒有套錯？
- **高年級（§5.10）**：是一個環節一步的步驟分頁嗎？圖片點得開、能滾輪放大嗎？答案與解析有沒有等老師分段公布？開場有沒有留老師的影片欄位、有沒有誤做一鍵表態題？每個環節都服務本節主技能嗎？每個新工具有沒有「老師示範 → 學生用另一個案例練習」？有沒有點名前一課的工具？
- **中年級——頁面會不會太長？** 區塊 ≥ 4 或超過約 3 個手機螢幕，有沒有拆成步驟分頁（§5.8）？進度列在手機寬度會不會橫向捲動？切步後作答有沒有保留？繳交與獎勵區是不是在最後一步、繳交確認有沒有回報各步狀況？
- 每個概念區塊是不是**至少有一個要動手的互動**？還是又變成只能讀？
- 作答/操作後**有沒有即時回饋**（對錯 ＋ 為什麼）？
- 有沒有一個**個人化生成器**，讓學生做出**屬於自己的**東西？
- 區塊順序＝引導軌跡順序嗎？一概念一色區嗎？
- 文字對嗎？中年級（§5.9）：夠短、夠口語嗎？**一個卡片正文超過 3 行、一句超過約 15 字的，都要刪；念給學生聽會不會分心？** 高年級（§5.10 第 3 點）：概念有沒有用完整句子說清楚、有沒有〔例〕與「發現了嗎」的歸納？
- 是**單一自足 .html** 嗎？打開就能動、手機能用、拖曳也能點選嗎？
- **★ 素材對帳：S7 採用的每一項視覺素材（照片、地圖、連結）都真的出現在成品了嗎？** 還是被 emoji 靜默取代了？未取得的有沒有用「待補：編號」佔位框標出來？
- 佈署情境對嗎？課堂本機檔就該用外部照片/地圖/連結把內容做厚（斷網有退回）；公開發布才全內嵌。
- 風格 token 整份一致嗎？年級主題對嗎？
- 涉及 AI／公開時，界線（查核/隱私）在頁面上出現了嗎（G8）？
- 換一個主題，這套**區塊清單＋生成指令**還走得通嗎？
- **評分設定**：有繳交的學習單有沒有內嵌 `grading-spec`（開放題評分設定＋`scoring` 配分，主要題加總＝20）？體驗題沒正解時是不是判「有沒有作答」？（見《學習單資料與提交規範》§2-e、§2-b）
