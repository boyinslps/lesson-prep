# HTML 互動教材設計規範（把引導軌跡變成「可動手」的學習頁 × 精確 AI 生成控制）

> 這份文件寫的是**過程的邏輯**與**如何精確驅動 AI 產出一頁 HTML 互動教材**，不是某主題的模板。
> 目標：拿到任何主題的引導軌跡，能生成一份**學生自己打開就能操作、有即時回饋、能個人化**的單檔 HTML 學習材料。
>
> **使用原則**
> - 例子一律標「〔例〕」，只為說明邏輯，換主題要重推。
> - 先讀 `教學活動設計規範.md`（引導軌跡與操作子 G1–G9）與 `簡報設計規範.md`（兩段式生成、五軸控制）。本規範是它們的互動版延伸。
> - **只做電腦版**：學生人手一台電腦、老師投影帶課。不做、不測手機／平板／觸控／響應式，新規則也不要加這類條文；桌面寬度驗證一次即可。

---

## 1. 核心：HTML 教材 ＝ 把引導軌跡「可操作化」

簡報是把軌跡外顯成**一頁一步讓學生看**；HTML 教材再進一步——把每一步變成**學生自己動手做、系統立刻回饋**的互動。

**簡報 → HTML 的關鍵躍遷：`被動看` → `主動做 + 即時知道對不對`。** 這帶來三個只有 HTML 能給的槓桿：
1. **即時回饋迴圈**：學生一操作，頁面馬上告訴他對／錯／為什麼（G6 預測—驗證變成秒級循環）。
2. **做中學**：能拖、能點、能試的東西，不用只用讀的（G4）。
3. **個人化產物**：學生輸入自己的資料，頁面**當場生出屬於他的成果**（G7）。

> 判斷「該做 HTML 而非簡報」：**有沒有值得學生反覆試、需要即時回饋、或能個人化的環節？** 有 → HTML；純線性講述 → 簡報就夠。

## 2. 從引導軌跡投影成互動區塊

把操作子（G1–G9）投影成**互動區塊型**。每個概念區塊盡量帶「一個要學生動手的動作」與「一個完成訊號」。

| 引導操作子 | 互動區塊型 | 學生要「做」什麼 | 即時回饋 |
|---|---|---|---|
| G1 製造勢能差 | **情境開場區** | 看對比／點一下切換「問題 vs 理想」 | — |
| G3 具象化抽象 | **比喻演示區** | 操作一個可玩的比喻（拖、點、滑）看概念怎麼動 | 畫面即時反應 |
| G6 預測—驗證 | **即時選擇題區** | 先選答案 | 立刻顯示對/錯 ＋ **為什麼** |
| G4 降低門檻 | **拖曳配對／填空／選單區** | 把積木/步驟拖進正確插槽、或從選單挑 | 對→鎖定並前進；錯→提示再試 |
| G5 通關條件 | **進度／徽章區** | 完成小關點亮徽章 | 進度條、徽章亮起 |
| G7 在地個人化 | **個人化生成器區** | 填自己的資料 | 當場產出**屬於他的**成果 |
| G8 給界線 | **查核／隱私提示區** | 勾選「可公開 vs 要隱藏」 | 標出紅燈項目 |
| G9 產出展示 | **匯出／分享區** | 複製成果、下載、或秀出來 | 一鍵複製成功提示 |

**版面原則**：**一個概念一個色區**，色彩幫學生分辨「現在在學哪一塊」；由上而下就是引導軌跡的順序。

## 3. 互動樣式庫（收斂成五種可靠的互動，換主題只換內容）

1. **即時選擇題**：點選後立刻變色顯示對/錯，並秀一句「為什麼」。（G6）
2. **拖曳/點選配對**：把卡片拖進正確插槽；全對才解鎖下一區。拖曳一律同時支援「點卡→點槽」。（G4）
3. **可玩的比喻演示**：一個小舞台，拖滑桿/點按鈕，即時看到概念行為。（G3）
4. **個人化生成器**：幾個輸入框 → 按鈕 → 依模板組出學生自己的成果。（G7）
5. **進度徽章**：完成各區點亮徽章＋進度條；全通關給完成畫面。（G5）

> 每個知識點**至少配一個「做」的互動**，不要整頁只有讀。逐欄寫作型的學習單另見 §5.16。

## 4. ★ 精確 AI 生成控制系統（HTML 版五軸）

沿用簡報規範的手法：**兩段式生成 ＋ 五軸夾住**——**結構／互動／文字／風格／技術**。

### 4.0 兩段式生成（總開關）
1. **第一段——先產「區塊清單」**：逐區列 `{區塊 · 對應概念 · 互動類型(§3) · 完成訊號 · 色彩}`。**人審核、增刪、調序。**
2. **第二段——生成單檔 HTML**：清單定案後才產出，不准自行增加區塊或互動。

### 4.1 結構控制軸
- **原則**：一個概念一個色區；由上而下＝軌跡順序；頁首一句話說明「這頁要帶你做到什麼」。區塊 ≥ 4 或超過約 3 個螢幕高就拆成步驟分頁（§5.8）。高年級見 §5.10，逐欄寫作型見 §5.16。
- **寫進 prompt**：「先只輸出**區塊清單**：逐區列【區塊名｜概念｜互動類型｜完成訊號｜色彩】，一概念一區、區塊數 ≤`N`；先不要寫 HTML，等我確認。」

### 4.2 互動控制軸
- **原則**：每個知識點至少一個 §3 的互動；**即時回饋**是必要件。
- **寫進 prompt**：「每個概念區塊必含一個 §3 互動，作答後**立即**顯示對錯與一句原因；配對全對才解鎖下一區；不要只有文字說明。」

### 4.3 文字控制軸（頁面是提示不是課本）
- **原則**：短、口語、指令式，對小學生說話。中年級只留關鍵字或提問（§5.9）；高年級用完整句子但每段要有存在的理由（§5.10）；逐欄寫作型見 §5.16 的字量目標。
- **預設上限**：區塊標題 ≤ **全形 14 字**；每段說明 ≤ **2 行**；按鈕/選項字 ≤ **8 字**；回饋訊息一句話。
- **寫進 prompt**：「文字精簡口語，對小學生；標題 ≤14 全形字；說明每段 ≤2 行；禁止長段落與課本式敘述；用『你、我們』與鼓勵語氣。」

### 4.4 風格控制軸
- **原則**：用**風格 token**（同簡報 §3）決定整體視覺；單檔內一致；依年級調主題（§5.5）。
- **符號**：操作型、逐欄寫作型的學習單（§5.11、§5.16）**頁面不用 emoji**，需要記號時用 ★☆✓☐ 這類文字符號或 CSS 圖形；其他頁面若用 emoji，只當標示，不能拿來取代素材（§4.5）。
- **寫進 prompt**：「風格 token：情緒【】、主色系【】、強調色【】、字體感【圓潤可愛/俐落科技】、圓角與陰影【多/少】。整份一致；每個概念一個色區但同一套風格語言。」

### 4.5 技術控制軸（讓 AI 產出「打開就能動」的單檔）

**先決定佈署情境（兩種規則相反，動筆前先確認）**
- **A. 課堂本機檔／GitHub Pages（預設）**：沒有 CSP 限制 → **可、且應**用外部資源把內容做厚：真實照片、地圖 iframe、外部網站連結。唯一要求：外部資源載不出時有替代文字或佔位框（`onerror`），主結構與互動不壞。
- **B. 受 CSP 限制的平台（如 Artifact）**：外部資源會被擋 → 才改「全內嵌」：圖片用 SVG／data URI，外部照片換成開放授權或內嵌版。

**鐵則（兩情境都適用）**：**S7 清單裡採用的視覺素材必須實際出現在成品**，不得用 emoji 或文字靜默取代；尚未取得的用明確佔位框標「待補：素材編號」。

- **單一自足檔**：一個 `.html`，CSS/JS 內嵌；不依賴本地建置流程（外部 CDN／圖床／地圖依佈署情境而定）。
- **字型與框架**：Tailwind CDN（`https://cdn.tailwindcss.com`）＋ 一組 Google Fonts。自訂 CSS 若寫了 `display`，要替會用 `hidden` 切換的元素明確補上 `.xxx.hidden{display:none}`，否則會蓋過 Tailwind 的 `hidden`。
- **純前端**：原生 JS；顯示切換用 `hidden`，不重繪整頁。
- **狀態保存**：可用 `localStorage`，**每次讀寫包 try/catch**，讀不到也要正常運作。
- **無障礙**：色彩對比足夠、可鍵盤操作、按鈕有文字。
- **學生輸入一律以純文字放回畫面**（先跳脫再插入），不信任任何作答內容。
- **寫進 prompt**：「輸出單一自足 `.html`，CSS/JS 內嵌；佈署情境＝【A／B】；原生 JS；hidden 切換；localStorage 需 try/catch；學生輸入跳脫後才放回畫面；只做電腦版。」

### 4.6 主控生成指令（可填模板）
```
你是這位教師的互動教材協作者。請為主題【主題】產出一份「單檔 HTML 互動學習頁」，
把一段引導軌跡變成「學生自己動手做、即時回饋、可個人化」的頁面。

■ 引導軌跡（來自教學活動設計）：【起點→目標與要推進的引導步驟/操作子】
■ 年級與風格：年級【中/高】；風格 token 情緒【】‧主色【】‧強調色【】‧字體感【】‧圓角陰影【】。
■ 舉例池（只能用這些，不足標「待補」，禁止虛構通用例）：【在地／個人真實例子】
■ 頁面類型：【互動練習頁（§3）／高年級帶課頁（§5.10）／操作頁（§5.11）／逐欄寫作學習單（§5.16）】
■ 個人化生成器（若有）：【輸入欄位：… ；輸出把它們組成：…】

■ 產出方式（務必兩段式）：
  第一段：先只輸出【區塊清單】（逐欄寫作型改列【步驟清單】：每步＝目標一句｜示範（影片或範例）｜換你寫的步驟｜檢查表），≤【N】項；先不要寫 HTML，等我確認。
  第二段：我確認後，輸出單一自足 .html：
    - 依頁面類型套用對應章節的版型（§5.8～§5.16）。
    - 文字依 §4.3；佈署情境依 §4.5，S7 採用的視覺素材務必實際嵌入。
    - 有繳交的學習單：依《學習單資料與提交規範》做識別列、題型標註、繳交資料、grading-spec（§2-e）。
```

## 5. 進階通則：把「能動的頁」做成「像老師的課」

> 自動生成常止於「互動骨架對了」，打開來卻像能動卻空心的頁：素材用 emoji 代替、例子是虛構通用、產物只是一句文字、視覺一體適用。以下每一條都是可遷移的通則。

### 5.1 真實素材呈現型錄（素材本身就是教學內容）

| 素材型別 | 呈現型 | 做法 |
|---|---|---|
| 操作截圖／實拍照 | **圖文交錯卡** | 白框＋陰影的大圖，一張圖配一段說明，左右交替排；圈點關鍵處；可點開放大 |
| 影片 | **內嵌 或 海報卡** | 學生要反覆看、跟著做的示範 → **直接內嵌**；只是老師帶看一次的長片 → 海報卡（縮圖＋一句「x:xx–x:xx 在講什麼」＋連出原片） |
| 網站／文章 | **預覽卡** 或 **真實任務導引** | favicon／og 縮圖＋標題＋開啟；或給連結＋任務，帶學生去官方站自己操作 |
| 結構化資料（門票／時間／地址） | **標籤小格** | labeled chips 格狀排，填真實數字 |

### 5.2 具體性：真實、在地、可查證
- 任務、例子、數據一律用**真實且在地的具體事物**（真地名、真數字、真連結），不用虛構通用例。
- **檢驗**：學生能不能真的照著去做、或查得到？不能 → 還是佔位例，重寫。

### 5.3 個人化產物要「看得見、帶得走」
- G7 的產物是一個學生可帶走的成品（一張卡、一份表、一張圖），不是一句回饋。
- 做法：輸入 → 套模板 → 先在螢幕長出成品 → 提供匯出（`canvas` 畫成 PNG 下載）＋「一鍵複製文字」當退路。
- 要讓學生之後取回自己的成品，見《學習單資料與提交規範》§3-c。

### 5.4 承重比喻要緊接「預測測驗」
- 每個具象化比喻（G3）後面緊接一個用該比喻能預測的小測驗，確認學生真的接住了比喻。〔例〕「主題像速食店套餐」→ 立刻問「自然風景套餐你會選哪些景點？」

### 5.5 年級分級：不只換皮，連「頁面的角色」都不同

| 參數 | 中年級（3–4） | 高年級（5–6） |
|---|---|---|
| 基礎字級／行高 | 18px＋／1.7，大按鈕、多留白 | 稍小、密度可高一點 |
| 情緒與色 | 暖色、圓潤可愛 | 冷色，卡片色區分環節 |
| 頁面角色 | **學生自學的步驟頁**（§5.8） | **老師帶課的教學活動頁**（§5.10）；操作／寫作課用 §5.11、§5.16 |
| 文字 | 關鍵字＋提問（§5.9） | 完整句子說明概念，附〔例〕與歸納 |
| 互動深度 | 點一下、選一個、填一格 | 判斷＋**說出證據**、分類、比較、動手查證 |

把中年級的版型（只留關鍵字、單選表態）套到高年級，學生會覺得幼稚、也練不到推理。

### 5.6 情感入口與交出前自檢
- **入口**：開場一個人人能答、沒有錯答案的問題，依回答給不同鼓勵。（高年級不用一鍵表態題，見 §5.10）
- **出口**：交出前一份勾選或自動檢查清單，把通關條件變成學生自己看得到的項目。

### 5.7 進度里程碑要「有意義」
- 進度／徽章／星星綁**完成一個真任務**（填滿一欄、做出一張表），不是每次點擊都 +1。

### 5.8 長頁拆成「學習路徑」步驟（中、高年級都用）
- **什麼時候拆**：區塊 ≥ 4，或頁高超過約 3 個螢幕。一兩屏看得完的頁不必為拆而拆。
- **通則**：
  1. **一步＝引導軌跡的一個階段**（一個主要動作），每步約 1～1.5 個桌面螢幕。
  2. **頂端固定進度列**：圓點＋短名稱（≤ 4 字），可點擊跳步，預設不鎖定。步驟太多時合併步驟，不要縮小圓點。
  3. **每步底部**「← 上一步」「下一步：〈名稱〉→」。
  4. **完成標記綁真任務**：有作答的步驟做完才畫 ✓；純閱讀步驟走過就算。
  5. **切步不丟狀態**：只用 `hidden` 切換、不重建 DOM；切步後捲回頂端。
  6. **交出放最後一步**：繳交按鈕與完成獎勵區（《學習單資料與提交規範》§3-b）；繳交確認對話框回報各步的完成狀況。
  7. **無障礙**：圓點是真的 `<button>`，當前步驟 `aria-current="step"`，每顆有 `aria-label`（「第 n 步：名稱」）。
- **寫進 prompt**：「區塊 ≥ 4 或超過 3 個螢幕高時改成步驟分頁：頂端固定進度列（圓點可點跳步）；每步底部上一步／下一步；hidden 切換保留作答，切步後捲回頂端；完成 ✓ 綁真任務；繳交與獎勵放最後一步。」

### 5.9 中年級文字：「關鍵字＋提問」，不是說明文
- 中年級學生網頁上超過一兩行的字幾乎不會讀，會直接找按鈕。
  1. 每個區塊只留**關鍵字**或**一個提問**；說明用詞組＋符號（`走路 → 排很多站`）。
  2. **一句只講一件事、≤ 15 字**；一張卡片正文 ≤ 3 行。更多解釋交給老師口頭講或圖／範例。
  3. 結論一句話收尾，不寫成段落。
  4. **操作步驟＝動詞開頭的短句**，一步一行，快捷鍵用 `<kbd>`。
  5. 能用截圖、照片、標籤小格說清楚的，就不寫字。
  6. 例外、備案、「為什麼」刪掉，或縮成一行小字。
  7. 提示訊息（成功／失敗／空白提醒）≤ 15 字，說「現在要做什麼」。
- **檢驗**：把頁面念給四年級學生聽，他聽到一半會不會分心？會 → 繼續刪。

### 5.10 高年級（5–6）：老師帶課的教學活動頁
- 高年級的頁面是**老師投影帶課、學生同步操作**，不是學生自己走完的自學頁。
  1. **一個環節一步**（§5.8 的步驟分頁），每個環節一張 `border-4` 大色卡；圖片一律可點開放大（滾輪縮放、拖曳、雙擊還原、Esc 關閉）。
  2. **老師分段公布**：答案、解析、全班統計放在等老師公布的區塊，公布鈕在各環節標題旁（《學習單資料與提交規範》§5-8），全班同步揭曉。
  3. **文字是「說明」不是「關鍵字」**：用完整句子講清楚概念，可有兩三行；常用句型「還記得上一課的…嗎？」「〔例〕…」「發現了嗎？…」「想一想：…」。
  4. **互動要練到推理，不是表態**：開場預設留一個**老師的開場影片欄位**＋一句「想一想」，不做「你會不會／你覺得呢」的一鍵表態題；其他常用型：分類、比較、評分（星等＋理由）、動手查證（附證據網址）。
  5. **前後課接起來**：每節至少一處點名前一課的工具並拿來用；結尾「今天你帶走的能力」＋下一課預告。
  6. **示範 → 練習成對**：每個新工具先「老師示範」，緊接「換你查」，用**另一個**真實案例讓學生自己做，由淺到深排。
  7. **真實素材做厚**：網傳擷圖、查核圖卡（標出處）、內嵌影片、延伸閱讀連結卡。
  8. **聚焦一個主技能**，所有環節都服務它；全班投票分布、留言牆預設不做，老師要求才加。
- **檢驗**：投影出來，老師能不能照著一路帶完一節課，而且每個環節學生都得「給證據」才能作答？

### 5.11 操作型步驟：照「實際操作的順序」排、少切換視窗
1. **照實際操作順序排，不照知識分類排**：某個操作在學生**真的要用到它的那一刻**才教，不提早做成獨立的複習步驟、也不教兩次。判斷法：這一步做完，學生手上有沒有東西可以馬上套用它？
2. **同一個視窗的事一次做完再換**：先列出整節課會碰到的視窗／工具，依「在哪個視窗做」分段；非切不可時，頁面寫清楚「去哪 → 做什麼 → 回哪」。
3. **開工動作放最前面**：開瀏覽器、從 Classroom 打開文件、改檔名，做完才開始真正的操作。
4. **前面填過的答案直接帶到後面**：到「寫進文件」那一步時，學生之前在學習單填的內容直接顯示在旁邊（可附複製鈕）。
5. **文件照由上到下的欄位順序寫**：一欄一張小卡＝要寫什麼＋去哪裡拿＋操作影片。
6. **影片貼著操作**：放在操作正下方或左右並排，不收進「卡住了？看影片」摺疊區，也不集中在最後。同一支影片只放在學生真正操作的那一步。
7. **繳交前自我檢查的順序＝操作順序**。
- **檢驗**：照頁面從上到下做一遍——要切換幾次視窗？有沒有操作講了兩次？每支影片是不是就在它的操作旁邊？

### 5.12 步驟卡元件：示範影片與操作小步
- **元件**：`引導規範/stepcards/`（`stepcards.css`、`stepcards.js`、`inject.py`）。頁面寫 `data-sc`／`.sc-slide`／`.sc-media[data-src,data-poster]` 標記，生成後執行 `inject.py` 內嵌（idempotent）；改了元件要重跑。
- **預設平鋪**（`class="sc sc-flat"`）：一步裡的小步垂直攤開、自動編號，不在頁面裡切換上一小步／下一小步，也不藏進「點開才看」。只放一支影片時加 `sc-nonum`。
- **一張卡＝一句話（≤ 15 字，關鍵詞加粗）＋一支影片**；影片已有步驟字幕時，頁面不再重講。
- **影片不切碎**：一個操作一支**完整**的示範影片（從開始到完成），學生看一次就知道整件事怎麼做；只有一個環節真的包含好幾個可以分開做的操作時，才一個操作一支。影片靜音循環、點一下暫停，看不到的不載入。
- **左右並列**（`sc-split`）：說明短、影片是整個畫面的小步，左文右片一眼看完；影片很窄或要搭大圖時維持上下。
- **產出寫在外部文件、頁面偵測不到時**：每欄放「這欄寫好了」讓學生自己標，頂端分頁鈕顯示 ✓。
- **接續上週的課（選用）**：最前面放「我現在做到哪」A／B／C 入口與「先想再點開」的複習翻卡（≤ 4 張）；有存檔進度時另放「拿回上次的進度」（《學習單資料與提交規範》§3-f）。
- **檢驗**：投影出來，後排的學生看得清一小步在做什麼嗎？一個畫面超過 15 個字（不含範例）就拆。

### 5.13 設計決策與老師的交代，不要出現在學生頁面上
1. **頁面只放學生此刻要看、要做的內容。** 設計取捨（為什麼不做 X、為什麼砍掉某活動）寫在 `05_教學活動流程.md` 給老師看。
2. **不說「我們不做什麼」**：界線用正面規則直接講（不寫「今天不玩換臉」，寫「臉和聲音別隨便交出去」）。
3. **老師交代的調整（配分改了、某題選做、步驟跳過）→ 改資料與行為，不加說明文字**：不計分就改 `qtypes`／`grading-spec`，跳過就拿掉那一步。確實需要學生知道的，用一句自然的題幹語氣，不用「老師說」「本題改為」這類後台口吻。
4. 頁尾、卡片裡寫給自己或老師的過程字眼（「依評估結果」「這是教學設計」）一律移到教案文件或 HTML 註解。
- **自檢**：把頁面上每一句話念給學生聽，是在教他東西，還是在向誰交代我為什麼這樣做？後者刪掉或搬走。

### 5.14 學生看得到的文字不寫年級
- 同一份教材常給不同年級用。`<title>`、頁首副標、頁尾、步驟名稱、按鈕與提示都**不寫年級或學期**（不寫「五年級上學期」「五上」），只留課次與單元名。
- 檔名、資料夾名可以保留年級；`worksheetId`、`lessonPath`（如 `g5-L06`）是資料鍵，**不要改**，改了既有繳交會對不上。
- 截圖、操作影片裡露出的課程名稱也要檢查，必要時遮蓋。
- **自檢**：別的年級的學生打開這一頁，有沒有任何一個字讓他以為這不是給他的？

### 5.15 老師臨時填入的設定：`textSettings`
- 要等上課前才確定的內容（例如校內區網的遊戲網址）不寫死在 HTML，由老師在 `#admin` 填入，存進 `quizzes/{worksheetId}`，學生端即時看到。
- 做法（引擎已內建，見 `materials/五年級上學期/_build_L05_L06/engine.js`）：設定檔加 `"textSettings": ["gameUrl"]`；學生區塊 `data-set-show="gameUrl"`（沒填就隱藏）、連結 `data-set-href="gameUrl"`；老師面板 `data-set-admin`（預設 `hidden`）內放 `data-set-input`／`data-set-save`／`data-set-stat`。網址必須以 `http://` 或 `https://` 開頭；輸入框不放 placeholder；「還原」不清這類設定。
- 這類網址只放在繳交後的完成獎勵區；教師檢視模式（`?review=`）會把獎勵區拿掉。

### 5.16 ★ 逐欄寫作的學習單：課本式引導（一欄一頁、先看示範再換你寫）

> **適用**：學生要一欄一欄寫出一份產出（查證報告、規劃表、心得…）的學習單，中、高年級都用。
> **範本**：`materials/五年級上學期/_build_L05_L06/build_L05_fri.py`＋`engine_L05_fri.js`（五上 L05 週五版）。看的是編排邏輯，換主題要重推。

**為什麼這樣排**：小學生一次看到整頁說明、範例、步驟、好壞對照、檢查表，不知道先看哪裡，最後只會直接找輸入框。國小課本的做法是**一次一件事、照「目標 → 示範 → 練習 → 自我檢核」的順序出現**。

**整份的步驟順序**
```
開始 → 選素材 → 準備（找到要用的來源）→ 第 1 欄 → … → 第 N 欄 → 預覽全部內容 → 繳交
```
- **開始**只講四件事：填身分（年級、班級、座號）、拿回上次的進度、今天的任務＋N 欄清單、寫不完怎麼辦。不放範例、不放規則。
- **不另外做「老師示範」整步**：每一欄自己都有示範，提早集中示範只會讓學生先讀一大段、到要寫時又忘了。

**每一欄＝一步，分兩批出現**

1. **標題卡**：「第 n 欄／共 N 欄」＋欄名＋**本欄目標一句**（≤ 20 字，提問或動詞開頭，關鍵詞加粗）＋這欄的星星狀態。
2. **看老師怎麼做**（一進來就看到）：
   - **操作欄**：一支**完整的示範影片**，從頭到尾演完這個操作（§5.12）。
   - **寫作欄**：老師的示範文字。用**黃底**標出關鍵句、**橘色小標籤**標出「這一段在回答什麼」（〔例〕什麼事／會怎樣／在哪裡）。範例用老師自己的題材，不用學生會選的題目。
   - **需要先懂概念的欄**（〔例〕轉傳的 5 種原因）：**先說明、再示範**。一排概念卡（名稱＋一句說明）放在範例前面，範例的標籤對回概念卡。
   - **有兩種做法時**（〔例〕關鍵字找／智慧鏡頭找）：「方法一」「方法二」各一個小標＋各自的影片，標題寫清楚什麼情況用哪個。
   - 最下面一顆「看懂了，換我寫」。
3. **換你寫**（按了才出現）：
   - 右上角「**再看一次示範**」：捲回示範（扣掉頂端固定列的高度）、影片從頭播、示範框閃一下。
   - **最多 3 個步驟**，每步一句短話、動詞開頭。
   - 寫的時候要對照的東西（〔例〕5 種原因）在步驟下放一行提示，**不要讓學生往上捲**。
   - 輸入框**不放提示字**；需要時給「插入句型」按鈕。
   - 檢查表每項一句短話，邊寫邊即時打勾；「!」只提醒、不擋。
   - 已寫過、拿到星或老師檢視時，這一批直接展開。

**邊看邊寫**：要描述或判斷學生**自己選的素材**時，把那份素材（圖片可點開放大、影片可播放）直接放在「換你寫」最上面。引導與句型**依素材種類換**：
- 〔例〕圖片訊息：看圖上的字，說了什麼事？說會怎樣？在哪裡流傳？
- 〔例〕影片訊息：誰在做什麼？字幕或說話說了什麼？在哪裡流傳？
- 原則一句話：**看到什麼寫什麼**，不猜、不加自己的想法；看不出來的給一個明確的寫法（〔例〕「看不出來就寫『網路上』」）。

**讓學生自己寫，不用勾選代替思考**：原因、後果、理由這類推理題，給概念說明和示範之後讓學生**自己寫**，不做「勾選類型＋補一句」。勾選只用在本來就是選擇的欄（用了哪個工具、哪一家機構、標籤）。

**條件式欄位**：只有選了某個選項才需要的欄（〔例〕選了「關鍵字搜尋」才要寫輸入的字）預設隱藏，選了才出現；完成判定與檢查表跟著同一個條件。

**收集星星**（完成一欄的成就感）
- **門檻要低、品質靠老師口頭提醒**：一欄必填的都有寫、而且要寫的文字**超過 5 個字**（空白不算）就拿到一顆 ★；只需選項的欄（〔例〕只選了用的工具）選了就算。檢查表照樣顯示當提醒，但不擋星星——避免學生為了湊勾而卡關或氣餒，內容好不好由老師巡堂時帶。門檻數字集中在引擎的一個常數（`STAR_MIN`），要調只改那裡。
- 拿到時跳出「拿到第 n 顆星」（約 2 秒自動消失、不擋操作）；最後一顆提示「去預覽看看你的報告」。
- 看得到星星的地方：頂端進度列（★ n／N）、開始頁的欄位清單、每欄標題卡、預覽、繳交頁、繳交後的獎勵區。
- 重新整理、拿回進度、老師填入示範答案時**不慶祝**；同一欄只慶祝一次。
- 用 ★☆ 文字符號，不用 emoji；頁面其他地方不要再用星星表示別的意思（〔例〕難度改寫成「難度：簡單／中等／較難」）。

**預覽全部內容**（倒數第二步）：把學生寫的 N 欄排成一份報告。表頭＝選的素材＋收集到幾顆星；每欄＝狀態、★/☆、內容（保留換行、網址可點）、「去改／去寫」跳回那一步，改完回來即時更新。內容一律跳脫後才放回畫面。

**繳交頁**只放各欄狀態（還沒寫完的可「去寫」）＋繳交按鈕；不要再放一組跟檢查表重複的自查勾選。

**字量目標**：學生剛進入一步、還沒按「換我寫」時，看到的字約 **50～120 字**；開始頁 ≤ 200 字。超過就先刪補充說明。

**跨節完成與改版**：一節寫不完時用「先存檔交一次」（《學習單資料與提交規範》§3-f）。改版若調整了步驟，存檔進度要依步驟名稱換算到新步驟（同 §3-f）。

- **檢驗**：
  - 學生一進這一步，第一眼看到的是不是「本欄目標」和「老師示範」？
  - 要寫的時候，需要的東西（素材、提示、句型）是不是都在眼前，不必往上捲？
  - 有沒有哪個推理題變成了勾選題？
- **寫進 prompt**：「逐欄寫作學習單：一欄一步；每步先顯示『本欄目標一句＋看老師怎麼做』（操作欄放一支完整示範影片、寫作欄放用黃底與標籤標出重點的老師範例、需要概念的先放概念卡再示範），按『看懂了，換我寫』才出現最多 3 步、輸入框與檢查表，並有『再看一次示範』；描述學生選的素材時把素材放在寫的地方並依種類換引導；推理題自己寫不勾選；條件式欄位選了才出現；每欄寫超過 5 個字得一顆 ★（門檻低、品質由老師口頭提醒）；倒數第二步預覽全部內容可跳回修改；繳交頁不放重複自查；頁面不用 emoji；一進每步的字量約 50～120 字。」

> **一句話收束**：互動樣式庫（§3）給的是**能動**；這一節給的是**像課**——真實素材做內容、在地具體任務、可帶走產物、比喻接測驗、年級分級、有意義的里程碑、看得見的學習路徑、操作照實際順序且影片貼著操作、逐欄寫作照課本「目標 → 示範 → 練習 → 自我檢核」一次一件事出現。學生頁面不交代設計決策與老師的調整。

## 7. 生成後自檢

**素材與內容**
- S7 採用的每一項視覺素材都用 §5.1 的呈現型**實際嵌入**了嗎？未取得的有「待補：編號」佔位嗎？佈署情境（§4.5）對嗎？
- 任務與例子是真實在地、查得到的嗎？個人化生成器有讓學生做出**可帶走的成品**嗎？比喻後面接了預測測驗嗎？

**版型與節奏**
- 年級版型套對了嗎（§5.5）？區塊多的頁拆成步驟分頁了嗎（§5.8）？切步後作答有保留嗎？繳交與獎勵在最後一步嗎？
- 高年級（§5.10）：一環節一步？答案等老師公布？開場是老師的影片欄位而不是一鍵表態題？每個新工具都「示範 → 換你做」？
- 操作頁（§5.11、§5.12）：照實際操作順序？同一視窗一次做完？影片貼著操作、一個操作一支完整影片？
- 逐欄寫作（§5.16）：每欄先目標＋示範、按了才出現換你寫？有「再看一次示範」？描述素材時素材就在寫的地方？推理題沒有變成勾選題？星星門檻夠低（寫超過 5 個字就給）？有預覽全部內容？一進每步的字量在 50～120 字左右？

**文字與口吻**
- 中年級：一句 ≤ 15 字、卡片正文 ≤ 3 行，念給學生聽不會分心？高年級：概念用完整句子說清楚？
- 有沒有「今天不做○○」「這題改成可不做」「老師說…」這類後台口吻（§5.13）？有沒有寫出年級（§5.14）？
- 操作型與逐欄寫作型的頁面有沒有 emoji（§4.4）？

**技術與資料**
- 是單一自足 .html 嗎？打開就能動、拖曳也能點選嗎？學生輸入有跳脫後才放回畫面嗎？
- 有繳交的學習單：識別列、題型標註、繳交資料、`grading-spec`、靠椅子關卡都照《學習單資料與提交規範》做了嗎？
