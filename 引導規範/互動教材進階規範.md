## 0. 先看差異：自動生成基準線 vs 實際精修

> 使用者要求「先分析理解一遍，和原本自動跑出來的有哪些差別」。以下是 L01 從自動產物走到定稿的落差盤點——**每一條落差，就是下面一節規範的由來**。

| 面向 | 自動生成基準線（照舊規範跑出來的樣子） | 實際精修後（L01 定稿 `06_成品.html`） | 變成哪一節 |
|---|---|---|---|
| **使用者角色** | 只有「學生自己打開操作」單一角色 | **教師端／學生端雙模式**：學生作答；老師用 `#admin` 解鎖「公布答案」控制權 | §1 |
| **答案揭曉** | 學生點完當下自己看到對錯（單機、各看各的） | **老師一按，全班裝置同步翻答案**、各自顯示對幾題；老師看即時交卷統計 | §2 |
| **素材呈現** | S7 說「素材務必嵌入」，但初版常用 emoji／自編例子帶過 | **真實素材多形態呈現**：內嵌本機圖片／影片、YouTube 內嵌、連結預覽卡（favicon＋og 縮圖） | §3 |
| **題目設計** | 平鋪直敘、真假分組 | **反直覺排列**：真假穿插、「越扯越真、越有理越假」，製造被騙衝擊 | §4 |

## 1. 教師端／學生端雙模式（`#admin` 控制權）

**需求來源**：有些互動（尤其「猜真假／投票→揭曉」）需要**老師決定何時公布答案**，不能讓學生自己先翻。

**做法（極簡、可維護、單檔）**
- **預設＝學生模式**：一般網址打開就是作答介面，看不到任何老師控制項。
- **教師模式＝網址加 `#admin`**：`location.hash === '#admin'` 時才顯示老師工具列（公布／收回）。學生不知道這個入口即可。
- **控制項**：老師工具列固定在頂端，含「🎉 公布答案」「🔒 收回」與狀態列。

```js
var IS_ADMIN = location.hash === '#admin';
// 學生：只綁作答；老師：#admin → 顯示工具列 → 綁公布/收回
```

**安全誠實說明（務必寫進交付說明，不要騙自己）**
- `#admin`＋前端密碼是**遮蔽（obscurity）**，擋得住一般學生，**擋不住打開 DevTools 讀原始碼的人**。
- 若要「連答案都藏住」，走 §2 的 Firebase 兩階段（答案存後端私有區，公布時才寫入公開區）。**單檔可維護性**與**強安全**二選一，依這節課的風險決定，並在成品說明裡講清楚選了哪個。

## 2. 跨裝置即時同步對答案（Firebase）

**需求來源**：「全班各自的平板作答 → 老師一按，所有人同時翻答案並看到自己對幾題」。單檔 localStorage 做不到跨裝置，需要一個即時後端。**選 Firebase（Firestore + Auth）**：免伺服器、有即時監聽、規則可控。

### 2.1 兩種模式共存（可維護第一）
成品**同一份檔**同時支援：
- **單機模式**（`firebaseConfig = null`）：`#admin` 密碼 `1234`，老師本機按公布→本機翻答案。離線可用、方便測試。
- **同步模式**（填入 `firebaseConfig`）：跨裝置即時同步（見下）。
- 用**動態載入** Firebase SDK：`firebaseConfig` 為 null 就完全不載入，離線頁不變慢。

### 2.2 資料模型（Firestore）
```
quizzes/{QUIZ_ID}                     # 主控文件
  revealed: bool                      # 老師寫：是否已公布
  revealedAt: timestamp
quizzes/{QUIZ_ID}/results/{uid}       # 每個學生一筆
  score: number, total: number, at: timestamp
```

### 2.3 角色與流程
- **學生**：匿名登入（`signInAnonymously`）→ 監聽主控文件 `onSnapshot`；`revealed` 變 true → 本機翻答案、算分、把自己的 `score` 寫進 `results/{uid}`。
- **老師**（`#admin`）：Email/密碼登入 → 按「公布」＝把主控文件 `revealed` 設 true → 全班 `onSnapshot` 觸發同步翻答案；老師監聽 `results` 子集合顯示「已交卷 N 人 · 平均 X / 8」。

### 2.4 Firestore 安全規則（樣板，換成自己的老師 email）
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isTeacher() {
      return request.auth != null && request.auth.token.email == "老師@學校.edu.tw";
    }
    match /quizzes/{quiz} {
      allow read: if true;                 // 任何人可讀「是否公布」
      allow write: if isTeacher();         // 只有老師能公布/收回
      match /results/{uid} {
        allow read: if true;                              // 老師端統計
        allow create, update: if request.auth != null
                              && request.auth.uid == uid; // 學生只能寫自己那筆
      }
    }
  }
}
```
- Authentication 需啟用：**匿名**（學生）＋**Email/密碼**（老師，Users 建一個帳號）。
- 部署到 GitHub Pages 後，Firebase → Authentication → Settings → **授權網域**要加 `帳號.github.io`，老師登入才不被擋。

### 2.5 答案藏匿的取捨（可選強化）
- **本規範預設**：答案寫在檔案 JS 裡（單檔好維護），Firebase 只同步「公布事件」與收分。搭配 `#admin` 遮蔽，對國小情境足夠。
- **要真藏答案**：答案存 `quizzes/{id}` 私有欄位、規則只給老師讀；老師「公布」時才把答案複製到公開欄位（兩階段寫入）。成品檔就讀不到答案。代價：老師要在後台維護一次答案。

### 2.6 登入狀態：一個瀏覽器只有一個 currentUser（踩過的坑，必讀）

**Firebase Auth 沒有「同時是老師又是匿名學生」這種狀態**——`auth.currentUser` 只有一個，而**任何一次 `signIn*()` 都會取代它並覆寫本機持久化的 session**。同一份學習單同時有「老師（Email/密碼）」與「學生（匿名）」兩條登入路徑，就一定會撞在一起。

**症狀**（真實踩過）：老師在 `#admin` 登入 → 按「預覽學生模式」（去掉 `#admin` 重載）→ 頁面走學生分支、無條件 `signInAnonymously()` → **教師 session 被匿名使用者覆蓋** → 按「返回教師模式」又要重打一次帳密。表面看像「登入沒有被記住」，其實是**被自己的另一條路徑洗掉了**。

**三條硬規則**

1. **判斷登入狀態一律用 `onAuthStateChanged`，不要直接讀 `auth.currentUser`。** 剛 `firebase.auth()` 之後同步讀一定是 `null`（session 還在非同步還原），會誤判成「沒登入過」而重新登入。
2. **登入前先確認「真的沒有」**——無論匿名或帳密，都先等 `onAuthStateChanged` 回報一次，有 session 就沿用。
3. **要有身分才能寫入的動作，用「有才用、沒有才登入」的 helper**（例如 `ensureAuth()`），不要每次動作都重新登入。

```js
// 學生分支：先確認沒有任何登入狀態，才簽名匿名（否則會洗掉老師的登入）
var unsub=auth.onAuthStateChanged(function(u){
  if(unsub)unsub();unsub=null;
  if(u)initFeed();
  else auth.signInAnonymously().then(initFeed).catch(function(){initFeed();});
});

// 教師分支（#admin）：已經是非匿名帳號就直接沿用，不要每次重整都跳密碼框
function teacherOnline(){
  showBar();
  var handled=false,unsub=auth.onAuthStateChanged(function(u){
    if(handled)return;handled=true;if(unsub)unsub();
    if(u&&!u.isAnonymous&&u.email)return wireTeacherUI(u.email);
    var email=prompt('教師 Email：',TEACHER_EMAIL); /* …登入後同樣呼叫 wireTeacherUI() … */
  });
}
```

- **把「登入成功後要接的事」抽成一個函式**（上例的 `wireTeacherUI(email)`）：沿用既有 session 與重新登入成功是兩條路徑，共用同一個收尾，才不會有一條路徑漏綁按鈕。
- **`isAnonymous` 要檢查**：匿名 session 也是 session，但它不該讓人進教師模式。條件寫成 `u && !u.isAnonymous && u.email`。

## 3. 真實素材的多形態呈現（把 S7 素材「做厚」）

**需求來源**：S7／§4.5 都說「採用的素材務必實際嵌入、不得用 emoji 靜默取代」。這一節把「怎麼嵌」講清楚——**依素材型別選呈現方式**（佈署情境 A 課堂本機檔，可外連）。

> **通則版已升級到** `HTML互動教材設計規範.md` §5.1「真實素材呈現型錄」（含圖文交錯卡、海報卡、標籤小格與佈局節奏）。這裡保留**同步／線上情境的實作細節**（og 縮圖、favicon 退化、FB 佔位）。

| 素材型別 | 呈現方式 | 要點 |
|---|---|---|
| **本機圖片**（老師存的截圖/照片） | `<img src="assets/xxx.jpg">` 內嵌 | 檔名用 **ASCII**（方便 push GitHub）；`onerror` 退回佔位框標明檔名 |
| **本機影片**（老師錄的示範） | `<video src="assets/xxx.mp4" controls>` | 同上；`preload="metadata"` |
| **YouTube 影片** | `<iframe>` 內嵌 `youtube-nocookie.com/embed/{id}` | 隱私版網域；`vidbox` 16:9 響應式框 |
| **文章／新聞／FB 貼文連結** | **連結預覽卡**（可點卡開原文） | 有 og:image 就當縮圖（`onerror` 隱藏）；沒有就用網站 favicon＋標題＋網域；FB 用藍底 📘 佔位 |

**連結預覽卡結構（可重用）**
```html
<a href="{url}" target="_blank" rel="noopener" class="preview-card">
  <!-- 縮圖：og:image ／ favicon ／ 📘 三選一 -->
  <div class="meta">
    <img src="https://www.google.com/s2/favicons?domain={site}&sz=32" onerror="this.style.display='none'">
    <div><b>{標題}</b><span>{網域}</span></div>
    <span>開啟 ↗</span>
  </div>
</a>
```
- **抓 og:image / 標題**：工作台 `/api/crawl`（server 的 `_fetch_meta`）已能取；或生成時用 WebFetch 補。抓不到就退化成 favicon 卡，**永遠有東西可看**（課堂可靠性優先於好看）。
- **鐵則**：連結預覽卡是「可點的預覽」，不是把整篇文章塞進頁面（版權＋雜訊）。真要看內文，點卡開原文。

## 4. 反直覺題目設計（猜真假型的加強）

**需求來源**：「猜真假」若真假分組、由淺入深，學生用直覺就能猜對，衝擊感弱。要**打散順序、真假穿插**，並刻意安排「**看起來很扯的其實是真的、講得很有道理的其實是假的**」，讓學生**先被自己的直覺打臉**，才有動機學查證。

- **穿插**：真假交錯（不要前 5 假後 3 真）；固定順序即可（不必每次隨機，方便老師喊「第 3 題」全班一致）。
- **反差選材**：至少 2–3 題「反直覺為真」（如：常吃南瓜手掌會變黃＝真；蜂蜜不會壞＝真）與幾題「像真的謠言」對打。
- **揭曉話術**：公布後點出規律——「越扯的越真、越有理的越假 → 直覺不可靠 → 所以要查證」。這句是這類活動的**教學收束**，務必寫進揭曉區。

## 5. 成果發布：本機預覽 → GitHub Pages（SSH）

> 成果展示分兩段：**先本機、再 GitHub**。這一段是「工作流程規範 S9 之後」的**新增 S10 發布階段**，也落地在工作台。

### 5.1 兩段式展示
1. **本機預覽（先）**：工作台成品區「🖥 本機預覽」——用本機伺服器開 `materials/.../{年級簡稱}_{節次資料夾名}.html`（成品檔名規範見 `工作流程規範.md` S9），相對路徑的 `assets/` 正常載入，斷網也能看。**先在這裡驗收互動與素材。**
2. **發布 GitHub（後）**：驗收無誤才「🚀 發布到 GitHub」，推上 Pages 拿到公開網址。

### 5.2 儲存庫結構（跟現有 `g4/L01` 一致）
```
pcclass/                      # GitHub repo（boyinslps/pcclass）
├── .gitignore               # 排除 *.md（備課過程檔）與憑證
├── g4/L01/index.html + assets/
└── g5/L01/index.html + assets/     # 成品檔（如 五上_L01_假消息與目的辨識.html）改名 index.html
```
- **年級→資料夾碼**：四上→`g4`、四下→`g4b`、五上→`g5`、五下→`g5b`（上學期為基底，下學期加 `b`；沿用既有 `g4`）。
- **節次**：取資料夾的 `L##` 前綴（`L01_假消息…` → `L01`）。
- **成品改名**：成品檔（`{年級簡稱}_{節次資料夾名}.html`，見 `工作流程規範.md` S9「成品檔名規範」）→ 發布為 `index.html`（GitHub Pages 慣例，網址乾淨）。

### 5.3 用 SSH 管理（不用 PAT）
- 金鑰：`C:\Users\Roki\.ssh\id_ed25519`（公鑰已加到 GitHub 帳號 `boyinslps`）。
- 遠端一律用 SSH：`git@github.com:boyinslps/pcclass.git`。
- 發布動作＝**整個節次資料夾一起推**（html＋assets，一次 commit），比單檔 API 可靠。
- 工作台 `/api/git-publish`：clone/pull 快取庫 → 複製 `index.html＋assets/` 到 `g{碼}/L##/` → commit → `git push`（SSH）→ 回傳 Pages 網址。

### 5.4 `.gitignore`（放 repo 最前面）
```gitignore

*.md
# 憑證 / 機密——絕不上傳
client_secret*.json
*credentials*.json
*.env
.env*
*.key
*.pem
# 系統暫存
.DS_Store
Thumbs.db
__pycache__/
```
> **只保留「網站＋素材」**：`.html` 與 `assets/` 進 repo，`*.md` 過程檔與任何憑證一律排除。工作台的 `config.json`（含金鑰）在 `工作台/` 底下，不在發布範圍內，天然不會被推上去。

### 5.5 上線後檢查
- GitHub → Settings → **Pages** 開 `main`／根目錄；網址 `https://boyinslps.github.io/pcclass/g5/L01/`。
- 若有 Firebase：授權網域加 `boyinslps.github.io`（§2.4）。
