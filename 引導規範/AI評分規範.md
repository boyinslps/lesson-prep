# AI 評分規範（通用評分系統）

> **定位**：所有開放題 AI 評分的最上層規則，適用於**每一份**學習單（不是針對某一課）。
> 實作在 `../評分平台/server.py`（`_grade_engine` 與三種評分方式）與 `../評分平台/teacher.html`（學習單設定的「開放題評分設定」、批改抽屜、批次評分）。
>
> **2026-09-23 改版**（取代舊的「整份一套評分規準＋逐題平均＋全部題目相對比較」）。起因：G4 L02「找出符合條件的景點」全班都答對，
> AI 卻因為景點不同給不同分數——舊總則第 2 條要求「和同儕比、分數該拉開就拉開」，套在查資料題上就變成硬拉分數。
>
> **相關**：題型定義與學習單怎麼標題號／題幹見《學習單資料與提交規範》§2、§2-e；分數怎麼合成最終成績見 `../評分平台/SPEC.md` §7-d、§7-j。

## 1. 核心原則

1. **每一題有自己的「題目規格」**：題幹、評分方式、標準、配分寫在同一個地方（`worksheets/{id}.questions[]`），一起送給 AI。
2. **AI 只判斷，分數由系統算**：AI 回答「這個項目符不符合條件」「這個檢核點有沒有做到」「這份作答是第幾級」，
   分數一律由伺服器依配分換算。所以**每題得分不可能超過該題配分**，也不靠 AI 自律。
3. **開放題總分＝各題得分加總**（不是平均）；開放題滿分＝各主要開放題配分加總。
4. **相同作答必同分**：同一題裡，正規化後（全半形、大小寫、空白標點都忽略）相同的作答只送 AI 一次，所有人共用結果。
5. **不確定就交給老師**：AI 不確定、或引用的證據在原文找不到，該題標「待確認」（列表黃色標籤、抽屜黃框），不猜。
6. **沒作答＝0 分，不送 AI**：去掉空白與標點後什麼都不剩就是沒作答，伺服器直接給 0。
7. **AI 沒回來就不給分**：某份作答 AI 重問一次仍沒回應，那位學生維持未評分，不補假分數。

## 2. 題目規格

```jsonc
{
  "qid": "q1",                 // 跟學習單的 data-qid 一致
  "prompt": "找出 2 個位於中西區的景點",   // 題幹
  "mode": "condition",         // levels｜checklist｜condition，見 §3
  "points": 4,                 // 配分（checklist 自動＝各檢核點加總）
  // levels 用
  "standard": "說出具體景點，並用查到的資料說明理由",
  "relative": true,            // 班級相對（預設：主要題 true、加分題 false）
  // checklist 用
  "checks": [{ "desc": "說出一個具體景點", "pts": 2 }, { "desc": "用查到的資料說明理由", "pts": 3 }],
  // condition 用
  "conditions": ["位於台南市中西區"],   // 每個項目要全部符合
  "basis": "以台南旅遊網的分類為準",     // 判斷依據（選填）
  "need": 2                    // 要找幾個
}
```

**沒設定的預設值**：沒有 `mode`＝`levels`；沒有配分＝主要題 10 分（舊資料有整份評分規準時用規準總分）、加分題 3 分；
沒有標準＝「有沒有回答到題目、內容是否具體、是否有自己的想法」。舊學習單（只有題幹＋整份規準）不用改設定也能評，
規準文字會當成每一題的標準。

**題幹從哪來**（優先序）：評分平台設定 → 學習單內嵌的 `grading-spec`（第一次開設定時自動讀入，之後可按「從學習單讀取」）→ 繳交資料裡的 `qtexts`（見《學習單資料與提交規範》§2-e）。

**學習單沒有內嵌設定時**：評分平台「AI 讀學習單產生」（`POST /api/gen-grading-spec`）讓 AI 先讀學習單網頁（題目附近的文字＋幾份學生作答長相），依 §3 選評分方式、寫題幹與標準；配分沿用目前卡片上的配分（依題數配好的），checklist 的檢核點配分會等比例調成加總＝配分。結果只填進卡片，老師檢查後按「儲存設定」才寫進 `worksheets/{id}.questions`——綁這份學習單，所有班級共用同一套標準（只有分級題的錨點依班級記錄）。

## 3. 三種評分方式：怎麼選

| 題目性質 | 評分方式 | 標準 | 範例 |
|---|---|---|---|
| 有唯一答案 | 不是開放題：標 `score`／`experience`，用 `data-correct` 或正則（見提交規範 §2-d） | — | 營業時間、選擇題 |
| 查資料、答案「符合條件即可」，可能的答案太多列不完 | **`condition` 條件查核** | 絕對：符合就對 | 找出 2 個中西區景點 |
| 開放但有明確要素 | **`checklist` 檢核點** | 絕對：做到就給分 | 說出景點＋用資料說明理由 |
| 表達想法、品質有高低 | **`levels` 分級** | 班級相對（可關） | 心得、你會怎麼做 |

### 3-a. `condition` 條件查核
- 伺服器先把作答切成片段（依 、，；/ 換行 空白），**AI 只做事實查核**：每個片段指的是哪個正式名稱（錯字、簡稱還原；
  「A和B」拆成兩個）、符不符合**全部**條件（true／false／不確定＝null）。AI 不評分、不寫評語。
- **得分＝配分 × 符合個數 ÷ need**（四捨五入）。學生多寫時**只採計前 need 個**，避免亂槍打鳥。
- **判定紀錄**（`worksheets/{id}.verdicts[qid]`）：`pieces`（片段→正式名稱）與 `items`（正式名稱→{ok, by, why}）。
  - 之後任何班級遇到同一個片段／項目直接沿用，**不再問 AI**，所以同一個景點永遠同一個判定。
  - 老師在「學習單設定」這題的判定紀錄點一下就能改判（符合→不符合→待確認），`by:'teacher'`；重新批次評分後用到的人一起更新。
  - 條件或判斷依據改了 → 儲存設定時自動清掉這題的判定紀錄（舊判定不再成立）。
- 判定為「不確定」的項目不給分、標待確認，由老師改判。

### 3-b. `checklist` 檢核點
- AI 對每個檢核點回答有沒有做到，做到的要**一字不改引用學生原文**當證據；伺服器檢查證據真的在原文裡，對不上就標待確認。
- **得分＝做到的檢核點配分加總**；配分＝全部檢核點加總。

### 3-c. `levels` 分級
- AI 給 0～4 級（4 優秀／3 良好／2 基本達成／1 明顯不足／0 與題目無關），**得分＝配分 × 等級 ÷ 4**（四捨五入）。
- **班級相對**（`relative:true`，主要題預設開）：各班程度不同，用同一把絕對尺會讓某班平均偏低，所以以該班當尺標：
  1. 第一次批次評分時，AI 先讀完這班這題的全部作答，**從這班挑出錨點**：最好的代表（4 級）、中間水準（2 級）、偏弱但有回答到題目（1 級）。
  2. 每份作答和錨點比較給等級。**品質相近給相同等級；大家都一樣好就都給一樣，不為拉開而硬分高低**（避免舊制的問題）。
  3. 錨點存在 `courses/{班級}.gradingAnchors[學習單][qid]`（錨點是學生作答原文，`courses` 只有老師讀得到，不放公開可讀的 `worksheets`）。
     之後同班重評、補交、單筆評分都用同一組錨點，尺標不會漂移。老師可在設定裡「重設本班錨點」。
     **只有這批不同作答 ≥ 5 種時才存錨點**（`ANCHOR_SAVE_MIN`）：上課中途只有少數人交就先評時，仍會以這批相對評分，
     但不把小樣本的尺標存下來綁住全班，等人數夠了再定。
  4. 題幹、標準或評分方式改了 → 儲存時自動清掉各班這題的錨點。
- 本班還沒有錨點時的單筆評分（批改抽屜）、或不同作答少於 3 種 → 退回**絕對標準**（依評分標準判斷）。
- `relative:false`＝絕對標準（加分題預設）。

## 4. 加分題

- 仍是 `bonusQids` 標記（見提交規範 §2-b），規格和主要題一樣可以選三種評分方式、設配分（沒設＝`levels` 絕對標準、3 分）。
- 加分題得分另外疊加（`bonusScore`＝各題加總），**不進開放題滿分、不影響主要開放題**。
- 非開放的加分題（`score`／`experience` 型）：**不進扣分池，答對才加分**（加分值＝逐題配分覆寫，沒填用預設扣分值）。

## 5. 評分總則（全域文字，可在 UI 改）

插在每一題 `levels`／`checklist` 的 prompt 最前面（`condition` 是事實查核，不用總則）。存在 `評分平台/config.json` 的
`grade_master_rubric`，留空＝跟著 `server.py` 的 `DEFAULT_MASTER_RUBRIC`：

```
【評分總則】（每一題都適用；各題的配分、評分方式與標準列在題目下方）
1. 只依照該題列出的評分標準或檢核點判斷，不要自己追加標準；不看字數多寡、用詞華麗。
2. 內容相同或意思相同的作答，必須得到相同的判斷結果。
3. 與題目完全無關的亂打、只抄題目，視為沒有達成任何標準。
4. 對象是國小學生：回饋語氣鼓勵但誠實，要具體可行（指出一個還可以補上的點），不要只說「很棒」這種空話。
```

- 配分上限、班級相對與否、條件查核怎麼判斷，都由系統依每題規格處理，**不要寫進總則**（尤其不要再寫「分數要拉開」這種全域相對規則）。
- `{max}` 會換成該題配分。預設內容改在 `server.py` 時，同步這一節。

## 6. 呼叫方式與回饋

- **批次評分**（`POST /api/grade-batch`）：老師按一次評完整班。後端**逐題**組 prompt——同一題的全班作答放在同一個 prompt、用同一套標準，
  各題平行呼叫（最多 4 條）；每題超過 40 種不同作答（條件查核 60 個片段）才分段，分段時沿用第一段挑出的錨點。
- **單筆評分**（`POST /api/grade`，批改抽屜）：同一套引擎，沿用判定紀錄與該班錨點。
- **評語**：每題一句（`levels`／`checklist` 由 AI 寫；`condition` 由系統依判定組出「符合：…；不符合：…（理由）；還少 N 個」），
  組成學生評語（多題時「【q1】…　【q2】…」），所以評語一定和分數一致。
- **AI 設定**：不強制 temperature（目前用的 Gemini 3 官方建議維持預設，調低反而可能出錯）；一致性靠去重、判定紀錄、錨點與系統計分保證。

## 7. 存進 Firestore 的欄位

| 位置 | 欄位 | 內容 |
|---|---|---|
| `worksheets/{id}` | `questions[]` | 題目規格（§2） |
| | `verdicts{qid}` | 條件查核的判定紀錄（§3-a） |
| | `scoring.openFromPoints` | 開放題保留分數＝各題配分加總（每題主要開放題都有填配分時生效，見 SPEC §7-d） |
| `courses/{班級}` | `gradingAnchors{學習單}{qid}` | 班級相對的錨點 `{"4":…, "2":…, "1":…}` |
| `submissions/{id}` | `aiScore`／`aiMax` | 開放題得分加總／開放題滿分 |
| | `aiScores{qid}` | 主要開放題逐題得分 |
| | `aiDetails{qid}` | 逐題判斷細節（條件查核的項目、檢核點與證據、等級、評語） |
| | `aiFlags[]` | 需老師確認的題號；老師在批改抽屜儲存後清空 |
| | `bonusScore`／`bonusTiers{qid}` | 加分題（沿用舊欄位） |
