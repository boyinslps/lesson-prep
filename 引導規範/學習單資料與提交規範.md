# 學習單資料與提交規範（識別欄 · 題型標註 · 繳交 · 即時同儕動態 · 教師模式）

> 這份文件定義**所有互動學習單**（不論用共用套件 `student-submit.js` 或客製 JS）都必須遵守的
> **資料契約**：學生是誰、每題是什麼類型、繳交時送出什麼形狀的資料。
>
> **定位**：`HTML互動教材設計規範.md`／`互動教材進階規範.md` 談「頁面怎麼設計」；
> **這份談「頁面產出的資料要長什麼樣子」**——是評分平台能讀懂任何學習單的前提。所有新學習單一律照此實作。

---

## 1. 識別列（Identity Bar）——放在學習單最上方

**原則**：學生是誰，用**三個數字**唯一決定，不問姓名。

| 欄位 | 資料欄 | 限制 |
|---|---|---|
| 年級 | `grade` | 數字（4／5／6…） |
| 班級 | `className` | 數字，1～14（防呆：不接受更大的數字） |
| 座號 | `studentId` | 數字 |

- **位置與黏頂**：頁面最上方，一進頁面就先填；識別列**黏頂（sticky）**，所以任何「請補填身分」的提醒都不必把頁面捲回頂端，只要 `focus()` 到第一個空欄。
- **輸入限制**：`inputmode="numeric"` ＋ JS 即時剔除非數字；三欄都必填才能繳交。
- **持久化**：存 `localStorage`（key `wk_identity`），重新整理不必重填。
- **不問姓名**：三個數字已能唯一定位學生；需要對應 Google Classroom 帳號時由教師端另外匯入名單解決。提醒文字也不要寫「姓名」。

**參考實作**：`評分平台/student-submit.js` 的 `StudentSubmit.init()` 會自動注入識別列；客製頁面可仿造其 DOM 與驗證，只要資料契約一致（§3）。

## 2. 題型標註——每個作答元素都要宣告自己是哪一種

**題型只有三種**：`experience`／`score`／`open`，**每一個作答元素都必須標**。「加分題」不是第四種題型，而是疊在上面的**標記**（2-b）。

| 題型 | 代碼 | 特徵 | 送 AI 評分？ | 計入正確率？ | 計入完成度？ |
|---|---|---|---|---|---|
| **測驗題** | `score` | 有正確答案，且**這節課要正式評量** | ❌ | ✅ | ✅ |
| **體驗題** | `experience` | 有正確答案（可即時告訴學生對不對），但這節是體驗/暖身 | ❌ | ❌ | ✅ |
| **開放題** | `open` | 沒有標準答案，學生寫自己的想法/推論 | ✅ **只有這種送** | ❌ | （原文照送） |

`score`／`experience` 在學習單端就判好 `isCorrect`，送 AI 只會浪費又可能判出跟標準答案不一致的結果。評分總則見《AI評分規範》。

**判斷準則——先問「這節課的定位」，不是看「題目形式」**：
- 正式檢核學到了沒 → 客觀題標 `score`。
- 先接觸、有感、建立直覺（例如引發問題意識的第一節）→ 即使有標準答案也標 `experience`。
- 沒有標準答案、要看學生怎麼想 → `open`。

### 2-a. 標註方式（DOM 慣例）
```html
<div data-qid="q1" data-qtype="experience" data-correct="true">…</div>
<div data-qid="q9" data-qtype="open" data-qtext="你會怎麼判斷一則訊息是真的？">…</div>
<div data-qid="q2" data-qtype="score" data-correct="B">…</div>
```
- `data-qid`：同一份學習單內唯一。`data-qtype`：三選一（必填）；加分題另加 `data-bonus="1"`。
- `data-correct`（`open` 不用）：標準答案，多選用「、」分隔。
- 客製 JS 頁面若用自己的資料結構管理題目，**不必**硬套 data 屬性，但**繳交 payload 必須符合 §3 的形狀**——資料契約優先於實作手法。

### 2-b. 加分題＝標記，不是題型
- 加分題仍有自己的 `qtype`，另用 `bonusQids` 標記。
- **不進任何分母**（`accuracyRate`、`experienceCompletion` 都不算它）；**不進扣分池**（答錯／沒寫不扣分，寫得好才往上加）；分數額外疊加，`totalScore` 可超過 100（`../評分平台/SPEC.md` §7-f）。
- 誰給分：`score`／`experience` 型看 `isCorrect`；`open` 型一律送 AI——答案**同時放 `openAnswers`（送 AI）與 `bonusAnswers`（完成提示）**，評分方式與配分同主要題（沒設＝絕對標準、3 分，見《AI評分規範》§4）。
- 學生端顯示「加分題：已完成／尚未完成」，**不顯示會加幾分**。

> **「不計分」是指不進正確率，不是「不影響成績」**：`accuracyRate` 的分母只有 `score` 題；但評分平台的最終成績預設把 `score` 與 `experience` 合成扣分池，逐題看 `isCorrect`，錯一題扣一分（SPEC §7-d）——**體驗題答錯一樣會扣最終分**。真的不想影響成績的題目，不要給它 `data-correct`／別把 `isCorrect` 判 `false`，或直接標 `open`。
>
> **沒有正解可比對的體驗題＝看有沒有作答**：沒設 `data-correct`、或答案要等老師公布（公布前 `correct` 是 `null`）時，`isCorrect` 判成「有沒有作答」，不可以直接給 `false`。`score` 題沒有正解時維持 `false`，等老師公布。

### 2-c. 每題都有題號與配分
- 每一題（含加分題）都有 `qid`；開放題的題幹、評分方式、標準、配分寫在 `grading-spec`（2-e），非開放題的配分寫在 `scoring.itemPoints`。
- 配分由**評分平台**統一管理（老師可在「學習單設定 → 分數計算」改）；學習單端只要標好 `qid`／`qtype`／`bonusQids` 並提供 2-e 的初始設定。

### 2-d. 自由文字題的自動核對：正則表達式
答案因人而異、可能有多個都對（〔例〕「找出一個中西區的景點」）時，讓教師在 `#admin` 用正則當標準答案，學習單用 `new RegExp(pattern,'i').test(作答)` 判 `isCorrect`。
- 教師**直接在學生作答的那個輸入框**輸入 pattern，按「上傳答案」存進 `quizzes/{quizId}.surveyPatterns:{qid:pattern}`。
- 多個答案用 `|` 分隔；`test()` 是子字串比對，含其中一個就算對。
- 留空＝退回「有沒有填」；無效正則要 `try/catch`，失敗時退回「有沒有填」，不可整頁壞掉。

### 2-e. 題幹、評分設定與分數計算：出題時就寫好（備課平台產出 HTML 時必做）
1. **題幹隨繳交送出**：開放題加 `data-qtext`（`student-submit.js` 自動收成 `qtexts`）；客製頁面自己在 payload 放 `qtexts:{qid:"題目文字"}`。
2. **內嵌評分設定**：評分平台第一次開這份學習單的設定時會自動讀入，老師檢查後儲存：
   ```html
   <script type="application/json" id="grading-spec">
   { "summary": "這份學習單在教什麼（一句話）",
     "questions": [
       { "qid":"q1", "prompt":"找出 2 個位於中西區的景點", "mode":"condition", "points":4, "need":2,
         "conditions":["位於台南市中西區"], "basis":"以台南旅遊網的分類為準" },
       { "qid":"q_share", "prompt":"你最想帶家人去哪個景點？為什麼？", "mode":"checklist",
         "checks":[{"desc":"說出一個具體景點","pts":2},{"desc":"用查到的資料說明理由","pts":3}] },
       { "qid":"reflect", "prompt":"今天查資料時你遇到什麼困難？", "mode":"levels", "points":4,
         "standard":"說出具體困難與自己的解決方法", "relative":true }
     ],
     "scoring": { "base":100, "floor":80, "deduction":1, "itemPoints": { "q_price":2, "q_map":2 } } }
   </script>
   ```
   評分方式怎麼選見《AI評分規範》§3：有唯一答案 → 不是開放題；查資料、符合條件即可 → `condition`；有明確要素 → `checklist`；表達想法 → `levels`。內嵌設定沒有學生資料，放在公開頁面沒問題。
3. **`scoring` 怎麼寫**（對應 SPEC §7-d）：總分 100、起跳 80，**20 分依題目數量平均分給所有主要題**——非開放題寫在 `itemPoints`（答錯或未完成扣的分），開放題寫在 `questions[].points`（checklist 由檢核點加總）。〔例〕8 題非開放＋2 題開放 → 每題 2 分。除不盡時先給開放題多 1 分。**主要題配分加總要等於 20**；加分題另外加，不佔這 20 分。

## 3. 繳交資料契約（Firestore：`submissions` 集合）

**文件路徑**：`submissions/{worksheetId}__{grade}-{className}-{studentId}`（同一位學生重繳＝覆蓋同一份；例：`5-1-12`）

```jsonc
{
  "worksheetId": "g5-L01",
  "worksheetTitle": "假消息與目的辨識",
  "lessonPath": "g5/L01",
  "grade": 5, "className": 1, "studentId": 12,          // 識別列，皆為 number

  "answers": { "q1": true, "q9": "我會先查證再相信" },    // 扁平版：所有題目原值
  "qtypes": { "q1": "experience", "q9": "open", "q10": "open" },
  "qtexts": { "q9": "你會怎麼判斷一則訊息是真的？" },      // 開放題題幹（§2-e）
  "bonusQids": ["q10"],                                   // 有加分題才需要

  "scoreAnswers":      { "qidX": { "given": "B", "correct": "B", "isCorrect": true } },
  "experienceAnswers": { "q1":   { "given": true, "correct": true, "isCorrect": true } },
  "openAnswers":       { "q9": "我會先查證再相信" },
  "bonusAnswers":      { "q10": { "given": "我會看是誰發的", "completed": true } },

  "accuracyRate": null,          // round(答對 score 題/總 score 題*100)；沒有 score 題＝null
  "experienceCompletion": 88.9,  // round(已作答體驗題/總體驗題*100)
  "status": "submitted",
  "submittedAt": "<serverTimestamp>"
}
```

**欄位規則**
- `accuracyRate` 分母為 0 時是 `null`（不是 0，避免誤讀成「考了 0 分」）；沒有 `score` 題的學習單本來就是 `scoreAnswers={}`、`accuracyRate=null`。
- `experienceCompletion` 衡量「有沒有作答」，不是「答對了沒」。
- **`isCorrect` 是教師端算成績的唯一依據**：
  - **沒作答也要輸出這一題**，`isCorrect` 判 `false`——省略了等於空著反而不扣分。
  - 沒有正解的體驗題見 §2-b 末段；**多選題**自己決定怎樣算對，把結論落在 `isCorrect` 這個布林值上。
  - Firestore **不接受 `undefined`**：沒值寫 `null`，寫 `undefined` 整筆繳交會失敗。
- `openAnswers` 原文照送，不裁切。**沒有開放題就不必呼叫 AI**，教師端直接用客觀題算分。

### 3-b. 繳交流程（確認 → 繳交 → 完成獎勵）
- **按「繳交學習單」先 `confirm()`**，對話框回報這次交了什麼（各段完成狀況）。
- **繳交失敗用明顯的提醒視窗，不用 `alert()`**（函式 `failModal(title,msg)`）：
  - ①識別列沒填好 → 送出前就攔下，標題「還不能繳交！」，點名「年級、班級、座號」；②寫入失敗（`.catch()`）→「繳交失敗！」，提醒檢查身分與網路、再按一次、還不行就舉手。
  - 樣式：全螢幕半透明遮罩＋置中白卡、粗紅框、大圖示、紅色大標題、18px 以上粗體內文，缺漏欄位名用紅字；一顆「我知道了」。關閉後 `focus()` 年級欄，**不要捲動頁面**。
- **可以重繳**：成功後按鈕改成「重新繳交（覆蓋）」。
- **繳交成功才出現完成獎勵區**：頁面底部預設 `hidden` 的區塊（如 `#rewardBox`），**只在寫入成功的 `.then()` 裡**顯示並 `scrollIntoView()`；失敗分支絕不顯示。內容＝一句恭喜＋兩顆固定按鈕，配色跟著該份學習單：
  - 「打字英雄」→ `https://boyinslps.github.io/typehero/index.html`
  - 「更多遊戲」→ **`https://boyinslps.github.io/pcclass/games/`**（老師自架的學生許可資源入口網，維護方式見 `引導規範/game-portal/README.md`）。**不可**連到 Gemini 分享頁或任何第三方產生的暫時頁面。
  - 要增減學生可玩的網站：只改入口網，不用動任何學習單。做完新學習單或改完獎勵區，跑一次 `引導規範/game-portal/check.py` 檢查所有學習單的連結。
  - 教師檢視模式（§5-7）要把獎勵區與繳交按鈕一起拿掉。

### 3-c. 學生暫存區 `studentWork`：讓學生取回自己的作品
`submissions` 只有老師讀得到；要讓學生換電腦或隔天取回**自己的產出**（宣言、構想卡這類可帶走的成果），另存一份學生可讀的資料。**任何學習單都存進同一個集合 `studentWork`，不另開集合、不改規則。**
- **id**：`{worksheetId}__{grade}-{className}-{studentId}__{kind}`（`kind`＝這份學習單的哪個項目，一份可存多個）。**不要**拿這種 id 去寫 `submissions`，兩種 id 用兩個函式分開產生。
- **內容**：`{ worksheetId, kind, grade, className, studentId, data:{…}, text, updatedAt }`。`data`＝欄位原值（取回時灌回表單）；`text`＝要還給學生看的成果字串。**只放要還給學生的產出**，不放分數、不放其他題作答、不放個資。
- **上限**：頂層欄位 ≤ 12、`kind` ≤ 40 字、`text` ≤ 2000 字，身分欄位是數字。
- **何時存**：繳交成功後（best-effort，失敗只 `console.warn`，不影響繳交、不對學生顯示）。**何時取**：學生按「顯示我的〇〇」→ 先確認身分已填 → `get` → 灌回表單；表單已有內容先 `confirm()`；找不到或讀不到用友善的話說明。
- **只用 `get`／`set`**，不做全集合監聽。規則（`評分平台/firestore.rules` 的 `studentWork` 區塊）：已登入者可 `get`，不開 `list`；`create/update` 驗身分欄位與長度；`list/delete` 只有老師。
- **已知取捨**：識別只有三個數字，知道別人座號就讀寫得到他的暫存——內容低敏感所以接受，但**不要拿這條路存成績、其他題答案或個資**。
- ⚠ 規則要由老師把 `firestore.rules` 貼進 Firebase Console 才生效。

### 3-d. 產出寫在 Google 文件：老師從 Classroom 匯入，不要求學生貼回
- 學生在 **Classroom 作業**裡建立文件並繳交；老師在評分平台按「匯入 Classroom 文件」，文件全文寫進該題的 `openAnswers[qid]`（SPEC §7-p）。
- 學習單端：**不做「把文件內容貼回來」的大框**，改放「回 Classroom 作業 → 確認文件附在作業裡 → 按繳交」的短步驟；學習單繳交**不送該題**（避免空字串蓋掉匯入內容）。開文件要強調「一定要從作業裡開」。
- `grading-spec` 照樣寫這題的評分設定，題幹註明「老師從 Classroom 作業讀取文件內容」。
- 加分題也寫在文件裡：格子最後放「`⭐ 加分：…`」＋標籤行；匯入時從 ⭐ 那行到結尾自動拆成加分題答案。學習單仍送 `bonusQids`。

### 3-e. 課堂「靠椅子」提醒＋繳交等待
被老師記到「下課四步驟沒做確實」的學生，下次交學習單時要看到提醒、等幾秒才能交。
- **學生端掛法（每份有 `#submitBtn` 的學習單都要）**：生成後執行
  ```
  工作台/runtime/python/python.exe 引導規範/chair-gate/inject.py
  ```
  會把 `chair-gate.js` 內嵌進去（`<!--CHAIR-GATE-START-->`…`END-->`，idempotent；`--check` 只看狀態）。改關卡邏輯＝改 `chair-gate.js` 後重跑。前提：頁面已載入 Firebase compat，沒有就自動放行。
- **規則**：`chairLog/{年級-班級-座號}` 有 `pending:true` 的學生會看到提醒與累計次數，等待秒數依次數遞增（預設 `[3,10,20,30,60]`）；下課前 `graceMin` 分鐘內免等待但次數照記；等完繳交後 `pending` 改 `false`。**讀不到設定、逾時（4.5 秒）、沒身分一律放行**——這個關卡絕不能擋住學生交作業。
- **總開關只在評分平台**；學習單裡不放任何開關。
- **資料**：`chairSettings/main`（`enabled, steps, graceMin, periods`）、`chairLog/{grade-className-studentId}`（`dates, count, pending, servedAt…`），只存三個數字不存姓名；學生只能 `get` 自己那筆、只能把 `pending` 改成 `false`。
- 白板照片辨識與登記在評分平台完成（本機辨識、老師確認後才寫入），細節見評分平台的說明文件。

### 3-f. 斷點繳交：多節課才寫得完的作業
學生不必等到最後一步才交——**任何一步都能「先存檔交一次」**，老師後台立刻看到已繳交，學生下次用年級／班級／座號拿回進度接著寫。範本：`materials/五年級上學期/_build_L05_L06/engine_L05_fri.js`。
- **按鈕**：每步底下一顆「先存檔交一次」，**走同一顆 `#submitBtn`**（先設旗標 `pendingCk` 再 `click()`），靠椅子關卡照樣攔得到；使用者真的按最後一步的鈕（`pointerdown`／`keydown`）會清掉旗標＝正式繳交。說明只用一句：「寫不完先按，下次用同樣的年級、班級、座號拿回來」。
- **資料**：寫 `submissions/{ws}__{年級-班級-座號}`，多一個 `checkpoint:{final,step,stepName,done,total}`（`final:false`＝斷點）；沒寫的題照 §3 輸出。成功後存 `studentWork/{ws}__{年級-班級-座號}__progress`：`data:{state,step,done,v}`、`text`（摘要）。不必改 Firestore 規則。
- **取回**：開始頁的「拿回我上次存的進度」（先填身分）。找到就回到存檔時的步驟；這台電腦已有內容時先 `confirm()`。不做彈出視窗。
- **改版要能換算**：`data.v` 是存檔格式版本。改版調整了步驟（拿掉、插入、改順序）時，**版本號加一，並保留每個舊版本的步驟名稱清單**；取回舊版進度時，用「舊步驟名稱 → 新步驟名稱」換算到新的步驟編號，被拿掉的步驟對到最接近的那一步（〔例〕「標題」→「網址」）。舊資料裡已不存在的欄位留著無妨，但完成數要扣掉。
- **共用電腦**：`localStorage` 的作答帶 `_owner`（年級-班級-座號）；身分三格填好離開時，若這台電腦上是別人的作答，先 `confirm()` 再清空，不同意就把身分換回原本的號碼。沒換人時不要重畫畫面（會吃掉使用者正要點的按鈕）。

## 4. 即時同儕動態（Live Feed）——開放題的可選加值
讓學生送出後看到同儕的回應（G9 展示，但即時、同儕對同儕）。**非必要**——判準：別人的答案會不會讓我學到東西或改變想法？
- **路徑**：`feeds/{worksheetId}/messages/{autoId}`；文件 `{ qid, text, tag, at }`，`tag`＝「5年3班12號」；`text` 限長（約 ≤ 120 字）。推送前檢查身分已填。
- **顯示**：固定高度捲動容器，`onSnapshot` 即時進來，只留最新 N 則。
- **權限**：已登入（含匿名）可讀、可寫自己的；不可改刪別人的；老師可刪。規則見 `firestore.rules` 的 `feeds` 區塊。
- ⚠ **複合查詢要先建索引**：`where('qid','==',…).orderBy('at')` 沒建索引時 `onSnapshot` 會失敗，而學生只會看到友善訊息、畫面看起來像「還沒人留言」。console 的錯誤訊息附有「建立索引」連結。**做了留言牆就自己送一則測試留言確認真的出現。** 想避開：一份學習單的 feed 只放一題，只用 `orderBy('at')`。
- **推送與繳交是兩個獨立按鈕**，不要把推送藏在繳交裡。
- **推送成功後鎖住按鈕**（「已送出」），改過內容才解鎖；多題各自獨立。

## 5. 教師／admin 模式標準要求

每份學習單的 `#admin` 教師工具列都要符合：

1. **「預覽學生模式」＝真的變回一個全新學生**：清掉身分與這份學習單的作答快取 → 拿掉 `#admin` 整頁重載 → 用 `sessionStorage` 記旗標，讓重載後仍顯示「返回教師模式」浮動鍵。動作前先 `confirm()`。
2. **教師登入一次就好，而且不可以被匿名登入蓋掉**：判斷登入狀態一律用 `onAuthStateChanged`；學生分支**先確認真的沒有任何登入**才 `signInAnonymously()`；要有身分才能寫入的動作用「有才用、沒有才登入」的 `ensureAuth()`。寫法與原因見《互動教材進階規範》§2.6。
3. **標準答案只有一個來源＝學習單自己**（`data-correct`／內建資料／`#admin` 介面）。評分平台不提供逐題手填正解，只管分數怎麼算與 AI 評分規準。
4. **不對學生洩漏技術資訊**：學生看得到的文字一律用對小學生友善的話（「現在看不到同學的留言，晚點再來看看」），不出現「Firestore」「規則」「API」；技術細節只寫進 `console.warn`。
5. **「還原」清空課堂暫存，`submissions` 永遠不碰**：
   - 還原時把所有公布旗標寫回 `false`，並把**課堂即時分享**的資料整批刪除：`feeds/{worksheetId}/messages`（留言牆）、`quizzes/{quizId}/votes/{uid}`（即時投票／評分彙總）。先 `confirm()`。
   - **`submissions/*` 是正式繳交紀錄，還原的程式碼完全不能碰這個集合。** 同一題可以同時推送到 `feeds`（暫存、會被清空）和繳交進 `submissions.openAnswers`（永久保留），兩個寫入互相獨立。
   - 驗收：還原後確認 `feeds`、`votes` 已清空，且某份已繳交的 `submissions` 內容與 `submittedAt` 沒變。
6. **每題旁有「切換題型」按鈕**（只在 `#admin` 且登入後出現）：點一下依「體驗 → 檢測 → 開放」循環，寫回 `quizzes/{quizId}.qtypeOverrides:{qid:type}`（`merge:true`），透過 `onSnapshot` 同步所有裝置；學生繳交時**依當下題型分流**到三個答案 map。沒調整過的題目用預設題型（通常 `experience`）。加分標記不受影響；一題有多個子欄位時整題一起切換。
7. **「檢視答案」與唯讀重現學生作答**：
   - **檢視答案**：把資料庫與程式裡的正確答案直接**填進學習單本身的作答欄**（不是另開清單）；「還原」要一併清掉這些填進去的內容。
   - **唯讀重現**：學習單認得 `?review={submissions 文件 id}`，只有 `#admin` 且教師登入後才讀那筆文件；把 `answers` 灌回頁面自己的資料結構並重新 render（不要觸發繳交路徑）；套用後鎖住所有作答元件、隱藏繳交按鈕與獎勵區；頂端橫幅「檢視模式（唯讀）：X年X班X號 的作答」＋「離開檢視」連結。
   - 評分平台每列繳交紀錄的「檢視」用 `{url}?review={docId}#admin` 開新分頁；學習單沒登記網址時按鈕停用並說明原因。
8. **「公布答案」可以分段，按鈕放在對應段落旁**：每段一顆公布鈕（只在 `#admin` 登入後出現）、各自一個 Firebase 旗標（`merge:true`）；揭曉函式要**冪等**；「還原」一次收回全部階段（學生端偵測到任一旗標變回 `false` 就重新載入）。只有一段時一顆鈕即可。

## 6. 範例：五上 L01「假消息與目的辨識」怎麼分類

L01 是課程第一節，目的是「先讓學生被自己的直覺打臉、產生查證動機」，不是正式評量——所以沒有 `score` 題：

| 學習單元件 | qid | 題型 | 理由 |
|---|---|---|---|
| 8 則真假投票卡 | `v1`–`v8` | `experience` | 有正解，但這節是體驗衝擊 |
| 危害勾選（5 項） | `harms` | `experience` | 有預期答案，仍是感受題 |
| 危害推論短文 | `essay` | `open` | 學生自己的推論，送 AI 評分 |
| 你是怎麼判斷的？ | `reason` | `open`＋`bonusQids` | 開放型加分題：不進完成度、不扣分 |

→ `accuracyRate=null`；`experienceCompletion` 依 9 題計算（`reason` 不計入）；`essay`／`reason` 各有獨立的「推送給同學看」按鈕與留言牆。**先問這節課的定位是體驗還是評量，再決定標 `score` 還是 `experience`。**

## 7. 生成後自檢

**身分與繳交**
- 最上方有黏頂的識別列（年級／班級／座號、只收數字、班級 1～14、存 localStorage）嗎？
- 繳交先 `confirm()`、失敗用紅框提醒視窗（不用 `alert()`、不捲動）、成功後才出現獎勵區、按鈕改「重新繳交（覆蓋）」嗎？「更多遊戲」指向自架入口網（跑過 `game-portal/check.py`）嗎？
- 有 `#submitBtn` 的學習單跑過 `chair-gate/inject.py` 嗎（`--check` 顯示已是最新）？

**題型與資料**
- 每個作答元素都標了 `score`／`experience`／`open` 之一？分類理由是「這節課的定位」？
- 繳交資料符合 §3 的形狀？**每一題都有 `isCorrect`（沒作答的是 `false`）**？沒值寫 `null` 不是 `undefined`？沒有 `score` 題時 `accuracyRate` 是 `null`？
- 沒有正解的體驗題，`isCorrect` 是「有沒有作答」？加分題沒算進完成度、學生端沒顯示分數？
- 開放題帶了題幹（`data-qtext`／`qtexts`）？內嵌了 `grading-spec`，主要題配分加總＝20、加分題排除在外？查資料題用 `condition` 而不是 `levels`？
- 有取回功能的話：存進 `studentWork`（id 帶 `__kind`），`submissions` 的 id 沒被汙染、只用 `get`／`set`？
- 有斷點繳交的話：走同一顆 `#submitBtn`？`checkpoint` 與 `progress` 都有寫？改了步驟有沒有升 `v` 並能換算舊進度？

**教師模式**
- 「預覽學生模式」真的清快取＋去掉 `#admin` 重載？已登入的裝置進 `#admin` 不會再跳帳密？學生分支沒有無條件 `signInAnonymously()`？
- 每題有「切換題型」、會即時同步、繳交依當下題型分流？學生端看不到這顆按鈕？
- 「檢視答案」填進作答欄、「還原」會清掉；`?review=` 唯讀重現有鎖住元件與隱藏繳交／獎勵？
- 「還原」清掉 `feeds`／`votes`，完全沒碰 `submissions`？分段公布的旗標各自獨立、揭曉冪等？
- 畫面上沒有洩漏技術字眼？有留言牆的話自己送過測試留言、推送鈕送出後會鎖住？
