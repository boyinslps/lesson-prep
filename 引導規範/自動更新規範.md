# 自動更新規範（GitHub 託管 · 兩個平台共用同一套機制）

> **一句話**：每一台安裝端都是 GitHub 儲存庫的一份 `git clone`；
> 作者在自己電腦改完 push 上去，其他安裝端一開啟就會看到「有新版本可以更新」的橫幅，按一下就更新完。

---

## 1. 兩個儲存庫

本專案拆成兩個各自獨立、各自能更新的 GitHub 儲存庫（2026-09-21 教師定案）：

| 平台 | 儲存庫 | 內容 | 本機 port |
|---|---|---|---|
| **備課平台** | `boyinslps/lesson-prep` | `工作台/`（server 8770＋面板）、`materials/`（學習單成品）、`引導規範/`、`課程計畫/`、教學風格分析 | 8770 |
| **評分平台** | `boyinslps/grading-platform` | `server.py`（8780）、`teacher.html`、`student-submit.js`、`firestore.rules`、規格文件 | 8780 |

**為什麼拆兩個**：兩者是「連動但內容拆開」的獨立工具——評分平台可以單獨裝在只需要改成績的電腦上，
不必把整包教材（含 18MB 的 `materials/`）一起拉下來；反之備課時也不需要評分平台。
拆開之後兩邊各自有自己的版本號與更新節奏，互不牽動。

## 2. 為什麼用「git clone ＋ 只快轉」，不是自己寫下載器

| 方案 | 取捨 |
|---|---|
| **git clone ＋ `merge --ff-only`（採用）** | 更新＝一次 `git fetch`＋快轉，天生有版本紀錄、可回溯、可看 changelog；Windows 上不必處理「執行中的檔案被覆蓋」的鎖檔問題（git 自己會處理）。 |
| 下載 zip 覆蓋 | 要自己比對版本、自己解壓覆蓋，**正在執行的 server.py 被覆蓋**時 Windows 會鎖檔；也沒有回溯能力。 |
| GitHub Releases ＋ 安裝器 | 對「一個人維護、偶爾改一下」的規模是過度設計，每次發版都要多一道手續。 |

**只快轉（`--ff-only`）是刻意的**：絕不在老師的電腦上做三方合併，
因為一旦跳出衝突，現場沒有人能解。寧可更新失敗並明講原因，也不要把它弄成半殘狀態。

---

## 3. 設計鐵則：本機狀態一律進 `.gitignore`

**這條是整套機制能只靠快轉就成立的前提。** 凡是「這台電腦自己的」東西都不可以進 git：

| 類別 | 例子 | 理由 |
|---|---|---|
| 金鑰／憑證 | `config.json`（AI key、Google client_secret、token）、`client_secret*.json` | 外洩風險，且每台不同 |
| 本機環境 | `runtime/`（可攜式 Python）、`工作台/.pub_repo/`（發布快取）、`__pycache__/` | 每台不同、體積大 |
| 個別教師資料 | `timetable.json`（這台的排課） | 每台不同 |
| **學生資料** | 任何 `*.csv`／`成績*`／`名單*`／`繳交*` 匯出檔 | **正本只存在 Firestore，本機產物一律不留**（2026-09-21 教師指定） |

只要這條守住，安裝端的工作區永遠是乾淨的 → `git merge --ff-only` 永遠成功。
反過來說，**只要有人把本機狀態 commit 進去，那台電腦就再也不能自動更新**（會變成「無法快轉」）。

## 4. 版本號：`VERSION` 檔

儲存庫根目錄放一個 `VERSION` 純文字檔（例：`1.0.0`），給人看的版本號。

- **判斷「有沒有新版」不是看這個檔**，而是看 `git rev-list --count HEAD..origin/main`（落後幾個 commit）——
  這樣即使忘了改 `VERSION`，更新提示依然正確。
- `VERSION` 只負責**顯示**（「1.0.0 → 1.0.1」比「落後 3 個 commit」好懂）。
- 慣例：修 bug＝改第三碼，加功能＝改第二碼，資料契約有破壞性變更＝改第一碼（並在 commit 訊息講清楚）。

## 5. API 契約（兩個平台的 server.py 都實作同一組）

實作在各自的 `updater.py`（兩邊同一份程式碼，只差傳進去的儲存庫根目錄）：
備課平台傳 `ROOT`（`工作台/` 的上一層），評分平台傳 `HERE`（它自己就是儲存庫根）。

| 端點 | 動作 | 回傳 |
|---|---|---|
| `GET /api/update/check` | `git fetch` 後比對，**只讀不寫** | `{ok, isGit, behind, currentVersion, latestVersion, changes[{sha,date,msg}], dirty, dirtyFiles[]}` |
| `POST /api/update/apply` | `git merge --ff-only origin/main` | `{ok, version, fromVersion, needRestart:true, message}` 或 `{ok:false, error}` |

**容錯規則**：
- **不是 git 安裝**（直接複製資料夾過來）→ `isGit:false` ＋ 一句人話說明，**不報錯**，也不顯示更新橫幅。
- **連不上 GitHub** → `ok:false` ＋ 錯誤訊息；**前端靜默略過**，不可因此影響正常備課／評分。
- **工作區有未提交修改** → `apply` 直接拒絕並把檔名列出來，**絕不自動 `stash` 或強制覆蓋**（那會吃掉別人的東西）。
- `GIT_TERMINAL_PROMPT=0`：避免 git 在伺服器背景跳帳密視窗，把整個請求卡死。

## 6. 前端橫幅（兩個平台共用同一套行為）

- 頁面一載入就呼叫 `/api/update/check`；**只有 `behind > 0` 才顯示**橫幅，其餘情況完全不打擾。
- 橫幅內容：`有新版本可以更新：1.0.0 → 1.0.1（3 個更新）` ＋ 三顆鈕：
  - **更新內容**：展開 changelog（commit 訊息＋日期）。
  - **立即更新**：POST apply → 成功後把文字換成「已更新到 x.y.z，請關掉這個視窗重新啟動」並收起按鈕。
  - **稍後**：用 `sessionStorage` 記住，這次開啟期間不再提醒（下次重開才會再問，不會變成每次重整都煩）。
- **更新後一定要重新啟動**：server.py 本身可能被換掉，執行中的是舊的。訊息要明確講「關掉視窗重新啟動」，
  不要只說「更新完成」讓老師以為已經生效。
- **教師端（`評分平台/teacher.html`）的橫幅不用 emoji**，沿用該專案「教師端專業無 emoji」的鐵則；
  備課駕駛艙面板則可用（它本來就有 🧭🔄✂ 這類圖示）。

## 7. 發布新版（作者端，在這台電腦）

```bash
# 備課平台
cd D:\自動化教案生成工作流
# 改完東西後，視情況更新 VERSION
git add -A && git commit -m "說明這次改了什麼" && git push

# 評分平台
cd D:\自動化教案生成工作流\評分平台
git add -A && git commit -m "說明這次改了什麼" && git push
```

commit 訊息會直接出現在其他人的「更新內容」清單裡，**所以要寫人看得懂的話**（寫「修正繳交後不會跳出獎勵區塊」，
不要寫「fix bug」）。

## 8. 別台電腦怎麼安裝

```bash
git clone https://github.com/boyinslps/lesson-prep.git
git clone https://github.com/boyinslps/grading-platform.git
```

兩個儲存庫都是公開的，clone 不需要任何帳號或金鑰。裝完照各自的 README：
把 `runtime/`（可攜式 Python）複製過去、填自己的 `config.json`，然後雙擊 `.bat` 啟動。
**不要用「下載 ZIP」**——那樣裝出來的不是 git 工作區，之後不能自動更新。

## 9. 生成後自檢

- 本機狀態（金鑰、`runtime/`、課表、任何學生資料匯出檔）是不是**全部**都在 `.gitignore`？漏一個就會讓安裝端永遠無法快轉。
- `git log --all -- config.json` 是空的嗎？（確認金鑰從來沒進過歷史，不是只有現在被忽略）
- 沒有 git、連不上網、工作區髒掉這三種情況，前端是不是都**不會報錯也不會擋住正常使用**？
- 更新成功後的訊息有沒有明確要求**重新啟動**？
- commit 訊息是不是寫給人看的（會直接變成別人的更新說明）？
