# 課程進度與甘特圖規範（資料規格 · 彙整流程 · 隱私 · 給 AI 的操作說明）

> 這份文件定義備課平台「📊 課程進度」甘特圖的**資料契約**，以及**誰負責產生資料、怎麼檢查、哪些東西絕對不能放進去**。
>
> **定位**：甘特圖只負責「讀一份彙整好的 JSON 然後畫出來」（唯讀）。**資料不是這個專案產生的**——
> 由老師電腦上**另一個本機 Claude Code session**（有 Google Classroom 與 Firestore 權限）彙整，寫成
> `課程進度/進度彙整.json`（**不進 git**）。備課平台這邊的 AI（包含雲端／沒有金鑰的 session）**不用也不能**實作彙整。
>
> **誰該讀這份**：①被老師叫去「更新進度」的本機彙整 session → 讀 §2～§5；②被叫去「甘特圖壞了／改畫面」的 AI → 讀 §6～§8。
>
> **標示「預設」的規則**是本文件替彙整流程先定下的做法（因為彙整程式在另一個 session）；老師或實作時發現與實際不符，
> 請直接改這份文件，不要只改程式。

```
 Classroom API ─┐
                ├─→ 本機彙整 session ─→ 課程進度/進度彙整.json ─→ GET /api/progress ─→ 面板「📊 課程進度」
 Firestore     ─┘   （有權限；規則見 §3～§5）  （不進 git）            （唯讀）           （甘特圖）
                                  找不到檔案時 ──→ 課程進度/範例進度彙整.json（假資料，進 git）
```

## 1. 檔案與位置

| 路徑 | 進 git？ | 誰寫 | 說明 |
|---|---|---|---|

## 2. 資料規格（schema 1）

```jsonc
{
  "schema": 1,
  "generatedAt": "2026-11-04T16:00:00+08:00",          // 帶時區的 ISO 8601
  "term": {"name": "115 學年度第 1 學期", "start": "2026-08-31", "end": "2027-01-15", "weeks": 20},
  "courses": [
    {"id": "g4", "gradeLabel": "四年級", "title": "勝利小創客：台南小導遊",
     "lessons": [{"code": "L01", "name": "旅行經驗與主題發想", "plannedWeek": 1, "periods": 1}]},
    {"id": "g5", "gradeLabel": "五、六年級", "title": "勝利小創客：數位時代的校園安全", "lessons": []}
  ],
  "classes": [
    {"id": "407", "grade": 4, "course": "g4", "students": 26, "current": "L07",
     "lessons": [
       {"code": "L06", "status": "done", "firstDate": "2026-10-29", "lastDate": "2026-10-29",
        "submitted": 22, "total": 26, "source": "classroom", "note": ""}
     ]}
  ],
  "mappingNotes": [{"assignment": "第九週 交通方式與路程時間", "lesson": "L06", "needsConfirm": false}],
  "notes": []
}
```

### 2-a. 欄位

| 欄位 | 型別 | 說明 |
|---|---|---|
| `schema` | 整數 | 固定 `1`。格式有不相容改動時才加 |
| `generatedAt` | 字串 | 產生時間，**帶時區**。甘特圖右上角顯示「資料產生時間」，超過 7 天會標「已 N 天未更新」 |
| `term.start` | `YYYY-MM-DD` | **第 1 週的起點，應為星期一**。週次 N ＝ `start + 7×(N−1)` 起的 7 天 |
| `term.end`／`term.weeks` | 日期／整數 | 學期結束日、總週數（橫軸有幾格） |
| `courses[].id` | 字串 | **`g4`、`g5`**。與 Firestore `worksheetId` 前綴一致（`g5-L05`）。六年級也用 `g5` |
| `courses[].lessons[]` | 物件 | 計畫：`code`（`L01`…）、`name`、`plannedWeek`（計畫的起始週）、`periods`（要上幾節＝佔幾週，預設每週 1 節） |
| `classes[].id` | 字串 | **年級＋兩位班號**，例：四年級 7 班＝`407`、五年級 1 班＝`501`（＝Firestore 的 `grade`、`className`） |
| `classes[].grade` | 整數 | 4／5／6 |
| `classes[].course` | 字串 | `g4`／`g5`（六年級也填 `g5`） |
| `classes[].students` | 整數 | **人數**，不是名單 |
| `classes[].current` | 字串／null | 目前進行到哪一節，定義見 §2-d |
| `classes[].lessons[]` | 物件 | 該班各節的實際狀況（沒有資料的節次**可以省略**，等同 `not_started`） |
| `lessons[].status` | 字串 | 只能是 `done`／`partial`／`in_progress`／`not_started`／`skipped`，定義見 §2-b |
| `lessons[].firstDate`／`lastDate` | `YYYY-MM-DD`／null | 實際條的起迄；`not_started`、`skipped` 可為 `null` |
| `lessons[].submitted`／`total` | 整數 | 已繳交人數／應繳人數（通常＝`students`） |
| `lessons[].source` | 字串 | 目前使用：`classroom`、`firestore`、`both`、`manual`（老師手動指定，如 `skipped`）、`none`（沒資料）。畫面只當說明顯示，不影響繪圖 |
| `lessons[].note` | 字串 | 給老師看的一行說明（停課、補課、缺交多…）。**不可含個資**（§5） |
| `mappingNotes[]` | 物件 | 作業標題 → 節次的對應紀錄，見 §4。`lesson` 無法判斷時填 `null`（此時 `needsConfirm` 必為 `true`） |
| `notes[]` | 字串陣列 | 整份資料的備註，顯示在甘特圖底部 |

- **日期一律 `YYYY-MM-DD`**，不要用 `2026/10/29`、不要帶時間。從 API 時間戳轉日期時**一律先換成 `Asia/Taipei`（UTC+8）**再取日期，否則晚上交的會差一天。
- 不要加規格以外的欄位（驗證器會報錯），尤其不要為了「方便」把名單塞進去。

### 2-b. 狀態定義與「完成度判定」門檻

以 `submitted ÷ total` 判定，**用整數比較**（`submitted×10 ≥ total×8`），不要先四捨五入：

| status | 條件 | 甘特圖 |
|---|---|---|
| `done` 已完成 | **≥ 80%** | 綠 |
| `partial` 部分完成 | **30%–79%** | 黃 |
| `in_progress` 進行中 | **< 30%**（但至少 1 人有繳） | 藍 |
| `not_started` 未開始 | **無資料**（0 人繳交，或根本沒有對應作業） | 灰 |
| `skipped` 略過 | **老師明確說這班不上這節**（不是「沒人交」；`source` 填 `manual`） | 虛線框 |

邊界範例（30 人的班）：24 人＝80%→`done`；23 人＝76.7%→`partial`；9 人＝30%→`partial`；8 人＝26.7%→`in_progress`。
`status` 必須與 `submitted/total` 一致，驗證器會檢查（`skipped` 除外）。

### 2-c. 週次、計畫與快慢

- **今天所在週** ＝ `floor((今天 − term.start) ÷ 7) + 1`。今天不在 `1…weeks` 範圍內時，甘特圖不畫今天線、也不判斷快慢。
- 計畫條畫在 `plannedWeek` 起、連續 `periods` 週。
- **快慢** ＝ `今天所在週 − current 那一節的 plannedWeek`：**> 0 慢（橘）、< 0 快（綠）、= 0 持平（灰）**。
  多節（`periods > 1`）的課以**起始週**計算。`第 N 週` 的標籤是「學期第幾週」，不是班級自己的課序。

### 2-d. `current`（目前進行到哪一節）——預設

取該班**最後一個有資料（`submitted > 0`）的節次**：
- 它不是 `done`／`skipped` → `current` 就是它（正在做，或做到一半）。
- 它是 `done`（或 `skipped`）→ `current` 是課程裡的**下一節**（還沒開始）。
- 全部節次都完成 → `null`（甘特圖顯示「✓ 全部完成」）。

老師另有指定（例如「407 其實已經在 L08」）時以老師為準，並在該班 `note` 註明。

### 2-e. 沒有日期的節次怎麼畫

`not_started`、`skipped` 沒有日期，甘特圖會把它們**畫在前一節結束後、下一節開始前的空檔**當示意（灰色斜線＝未開始、虛線框＝略過），
不是真的起迄。**不畫在計畫週的位置**，因為落後的班那裡已經是別節的資料。

## 3. 資料如何產生（彙整流程）

**由誰做**：老師電腦上**另一個本機 Claude Code session**。它有 Classroom OAuth 與 Firestore 服務帳號（金鑰在老師電腦的 `D:\keys\`，**不進 git**）。
備課平台的 session（尤其是雲端環境）**看不到 Classroom、Firestore、Drive，也沒有真實資料**——被要求「更新進度」時不要假裝能做，請老師到本機 session 執行。

**資料來源**（兩邊合起來算「繳交」）：

| 來源 | 讀什麼 | 備註 |
|---|---|---|
| **Classroom API** | `courses.courseWork.studentSubmissions`：`state` 為 `TURNED_IN`、`RETURNED` 算**已繳交**；`NEW`、`CREATED`、`RECLAIMED_BY_STUDENT` 算**未繳交**。日期取 `submissionHistory[].stateHistory` 裡進入 `TURNED_IN` 的時間 | 既有的 `工作台/server.py` 已有 OAuth 與 `classroom_coursework`／`classroom_students` 可參考；`classroom.coursework.students` 這個 scope 讀得到 `studentSubmissions` |
| **Firestore `submissions`** | 文件路徑 `submissions/{worksheetId}__{grade}-{className}-{studentId}`，`status:'submitted'`、`submittedAt`（見《學習單資料與提交規範》§3） | `worksheetId` 如 `g5-L05` **直接就是 `課程-節次`**，不需要標題對應。可參考 `工作台/firebase_admin_rest.js` 的服務帳號讀法 |

**彙整步驟**（逐班逐節）：

1. 讀本文件 §2 規格與 §5 隱私規則。
2. 列出每個 Classroom 課程（＝班級）的作業清單，依 §4 把作業標題對應到節次；Firestore 依 `worksheetId` 直接分節次。
3. 每班每節算 `submitted`（**以人為單位去重**：同一位學生兩邊都有只算 1）、`total`（應繳人數）。**去重只在記憶體裡做，不可把學生識別寫進任何檔案**。
4. 依 §2-b 算 `status`；依 §2-d 決定 `current`。
5. 日期：`firstDate` ＝ 該班該節**最早**的繳交日；`lastDate` ＝ 該班該節繳交**大致結束**的日期。
   **預設：遲交（落在下一節 `firstDate` 之後才交的）不拉長 `lastDate`**，否則同一班的兩條會疊在一起。驗證器對日期重疊會給警告。
6. **斷點繳交**（`checkpoint.final === false`，見《學習單資料與提交規範》§3-f）**預設不計入 `submitted`**，並在該節 `note` 寫「另有 N 人斷點存檔」。
7. 同一節同時有 Classroom 與 Firestore 時，`source` 填 `both`；無法確定同一個人時取兩邊**較大值**並在 `note` 說明。
8. 寫入 `課程進度/進度彙整.json`：UTF-8、`schema: 1`；**先寫暫存檔再改名**，避免甘特圖讀到寫一半的檔案。
9. 跑驗證器（§6-b）。有「錯誤」就修到過；有「警告」要看過。
10. 把 `mappingNotes` 裡 `needsConfirm: true` 的項目**列給老師**（§4）。
11. 暫存與原始回應只放 `課程進度/_本機/`。**完成後確認 `git status` 看不到 `進度彙整.json`**。

## 4. 作業標題對應到節次

作業標題是老師手打的，沒有固定格式。**依序**套用，命中即停：

| 順序 | 規則 | `needsConfirm` |
|---|---|---|
| 1 | 標題含節次代碼（`L06`、`l06`） | `false` |
| 2 | 標題含該課程某節 `name` 的**完整字串**（忽略空白與全半形），且只命中一節 | `false` |
| 3 | 只有部分相符、或同時命中多節、或只靠關鍵字（例：「景點資料表（第二版）」） | **`true`**（暫填最像的一節） |
| 4 | 完全看不出來（例：「課堂回饋問卷」） | **`true`**，`lesson: null`，**不計入任何節次** |

- ⚠ **`第 N 週` 不可當依據。** 例：作業「第九週 交通方式與路程時間」是**實際上課的第 9 週**，但 L06 的計畫週是第 6 週；
  停課、段考、補課都會讓兩者分家。只看**名稱或代碼**，週次字樣忽略。
- **一份作業涵蓋多節**（例：五上 L05＋L06 合成一份）：每一節各寫一筆 `mappingNotes`（`assignment` 相同），兩節 `needsConfirm` 都填 `true`，並在 `note` 註明「與 Lxx 合併作業」。
- 一節有多份作業（週五版、補充版）：以**人為單位**，該節任一份主作業有交就算已繳交；有疑義時 `needsConfirm: true`。
- `mappingNotes` 沒有課程欄位。同一個標題可能同時像 g4 與 g5 的節次時，把課程寫進 `assignment` 文字裡（例：`四年級 景點資料表（第二版）`）。

### `needsConfirm` 怎麼處理

1. **照樣彙整**：對應不明的作業仍用「暫填的那一節」算進資料（甘特圖才有東西可看），但 `mappingNotes` 一定要標 `true`。`lesson: null` 的作業不算進任何節次。
2. **不可自己把 `true` 改成 `false`。** 只有老師說「對／錯，應該是 Lxx」之後才改。
3. **要問老師**：彙整完把所有 `needsConfirm: true` 的作業標題＋暫定節次列成清單給老師，一次問完。
4. **記下來**：老師確認的對應存進 `課程進度/_本機/標題對應.json`（`{"作業標題": "L06"}`）；下次彙整**先查這份**，查到的就直接當 `needsConfirm: false`，不要重複問。
5. 甘特圖底部會列出「⚠ 作業標題對應待確認（N 筆）」，老師打開面板就看得到還有哪些沒確認。

## 5. 隱私規則（最重要）

**這份資料只放「班級層級」的東西**：班級 id、人數、各節的繳交人數、日期、節次。

| 絕對不可以出現在 `進度彙整.json`（含 `note`、`notes`、`mappingNotes`） |
|---|
| 姓名、綽號、「王同學」「某某某」 |
| 學號、**座號**（包含「12 號沒交」「3、7 號缺交」這種寫法） |
| email、Classroom `userId`、submission id、學生個人的作業連結或作答內容、照片 |

- 要知道「誰沒交」是**老師當下在對話裡問**的事：彙整 session 可以回答，但**只在對話裡說，不寫檔**。
- Classroom／Firestore 的**原始回應含姓名與學號**：只留在記憶體；一定要落地時只放 `課程進度/_本機/`（已 `.gitignore`）。
- 進 git 的只有：規範、驗證器、**虛構的**範例。真實檔 `課程進度/進度彙整*.json` 與 `課程進度/_本機/` 都被 `.gitignore` 擋住。
  commit 前跑一次 `git status`，**看到它們出現就停**（如果曾被 `git add` 過：`git rm --cached 課程進度/進度彙整.json`）。
- 驗證器會做兩層防線：**欄位白名單**（規格以外的欄位一律報錯）與**個資字眼掃描**（座號／學號／姓名／email 等）。它抓得到字眼，抓不到「王小明」，所以彙整時要自己守住。
- 面板與 `GET /api/progress` **唯讀、路徑寫死**（不接受使用者傳路徑），沒有任何寫入 API。

## 6. 給未來 AI 的操作說明

### 6-a. 老師說的話 → 你該做什麼

| 老師說 | 你該做 |
|---|---|
| 「更新進度」「重新彙整」 | 你有 Classroom／Firestore 權限嗎？**有（本機 session）**→ 照 §3 做，再走 §6-b。**沒有（雲端／備課平台 session）**→ 直接說「我讀不到 Classroom 與 Firestore，請在本機彙整 session 做」，**不要編資料** |
| 「甘特圖沒出現／不對」 | 走 §6-c 檢查，再對照 §6-d |
| 「改甘特圖的畫面」 | 看 §8 的位置；**用範例資料驗證**；改完更新本文件與 `工作流介面規劃.md` |
| 「範例資料不夠／要多一種情況」 | 改 `範例進度彙整.json`（必須通過驗證器、必須是虛構資料） |

### 6-b. 重新彙整之後的檢查（依序，不要跳）

```bash
# 1. 驗證格式與完成度判定（Windows 用可攜式 Python；不給參數＝先驗真實檔，沒有就驗範例）
工作台\runtime\python\python.exe 課程進度\驗證進度彙整.py

# 2. 確認伺服器讀到的是「真實」檔（必須看到 "source": "real"）
curl.exe -s http://127.0.0.1:8770/api/progress
```

3. 開面板 → 頂列 **📊 課程進度**。右上角應該是「**資料產生時間：…**」。如果還是橘色的「**目前顯示的是範例資料**」＝沒讀到真實檔，看 §6-d。
4. 隨便點開幾個節次的滑鼠提示，確認繳交人數、日期跟 Classroom 對得上。
5. 若 `mappingNotes` 有 `needsConfirm: true`，確認底部的「作業標題對應待確認」已列出，並已告知老師。

伺服器**每次請求才讀檔**，更新 JSON 後**不用重啟**，面板按「🔄 重新讀取」即可。（改了 `server.py` 才需要重啟，見《自動更新規範》。）

### 6-c. `GET /api/progress` 怎麼看

| 回應 | 意思 | 甘特圖 |
|---|---|---|
| `{"ok":true,"source":"real","file":"課程進度/進度彙整.json", …檔案內容…}` | 讀到真實檔 | 顯示資料產生時間 |
| `{"ok":false,"code":"not_found","sampleAvailable":true}` | 真實檔不存在 | 面板自動改讀 `?sample=1`（範例），角落標「目前顯示的是範例資料」 |
| `{"ok":false,"code":"invalid_json","error":"…"}` | 檔案在，但壞掉 | **不會退回範例**（避免把假資料當真的）；面板顯示紅框錯誤 |
| `GET /api/progress?sample=1` | 強制讀範例 | 開發與展示用 |
| 404 `no route` | `server.py` 還是舊版（沒重啟，或沒更新到有這個功能的版本） | 面板的 📊 按鈕也還不存在 |

### 6-d. 常見錯誤

| 症狀 | 常見原因 | 處理 |
|---|---|---|
| 明明產生了檔案，角落仍寫「範例資料」 | 檔名不是**完全**等於 `進度彙整.json`；放錯資料夾；Windows 隱藏副檔名導致實際是 `進度彙整.json.txt`；伺服器是從別的資料夾的 `server.py` 啟動的（讀的是另一份 repo） | `dir 課程進度`；`curl.exe` 看 `file` 欄位寫的路徑 |
| 紅框「讀取或解析失敗」 | JSON 語法錯：尾逗號、單引號、註解、Python 的 `None`／`True`、檔案寫到一半 | `python -m json.tool 課程進度\進度彙整.json` 找錯誤位置；§3 步驟 8 要先寫暫存檔再改名 |
| 紅框「進度檔欄位不完整」 | 缺 `term.start`（`YYYY-MM-DD`）、`term.weeks`、`courses[]` 或 `classes[]` | 對照 §2 |
| 某個班沒出現在圖上 | 被「年級」或「只看落後的班」篩掉；該年級組被摺疊；`classes[]` 沒有它 | 取消篩選、點年級列展開 |
| 某班顯示「進行到 —」或快慢是「—」 | `current` 缺漏（`null` 且還有沒完成的節次）／不在課程節次裡；今天不在學期範圍內（不判斷快慢）；`course` 對不到 `courses[]` | 驗證器會抓；看右上標題列的「今天…」 |
| 全部班都顯示慢（或都快） | `term.start` 不是學期第一個星期一；電腦日期不對；網址帶了 `?today=` | 對照 §2-c 算週次 |
| 條的位置差一天、或兩條疊在一起 | 時間戳沒轉 `Asia/Taipei`；`lastDate` 被遲交拉長 | §2 與 §3 步驟 5；驗證器的「日期重疊」警告 |
| 顏色跟比例對不上（例：95% 卻是黃） | `status` 與 `submitted/total` 不一致 | 驗證器會逐筆指出 |
| 右上角出現「已 N 天未更新」 | 彙整太久沒跑 | 重新彙整 |
| `git status` 看到 `進度彙整.json` | 這個檔曾被加進索引，`.gitignore` 對已追蹤的檔案無效 | `git rm --cached 課程進度/進度彙整.json`，並確認內容沒上傳過 |

### 6-e. 測試小技巧

- 網址加 `?today=2026-11-04` 可**指定「今天」**（只影響甘特圖的今天線與快慢），範例資料是照這一天設計的：
  `http://127.0.0.1:8770/?today=2026-11-04`
- 範例資料涵蓋：g4＋g5、四／五／六年級、慢／快／持平、五種 status、2 節連上、同週加課、停課、略過、待確認對應。改範例時請保留這些情況。

## 7. 甘特圖怎麼讀

- **橫軸**：學期週次 `W1…W20`，下面是該週起始日；紅線＝今天，本週表頭底色加深。
- **縱軸**：年級分組（四／五／六，**點年級列可摺疊**，記在 localStorage），組內依班號排序。右側小字是該年級的落後／領先班數。
- 每班兩層：**上層細條＝計畫**（該課程各節 `plannedWeek`）；**下層粗條＝實際**（`firstDate`～`lastDate`，過短的條最小寬度約 24px，方便看到節次代碼）。
- **左欄**：「進行到 Lxx」＋ ▼慢 N 週（橘）／▲快 N 週（綠）／＝持平（灰）。
- **黑框**＝目前進行的節次；計畫層裡**同色外框**的是該班目前節「計畫應該在的位置」，兩者的距離就是快慢。
- 滑鼠移到任何一條：節次與單元名稱、狀態、繳交人數與百分比、起迄日（含星期與週次）、計畫週、`note`、資料來源；移到班級名稱則顯示快慢的算法。
- 上方可篩：**年級**、**只看落後的班**、**顯示計畫層**；🔄 重新讀取；🖨 列印／另存 PDF（A4 橫向、自動隱藏操作列、一律淺色）。
- 底部：待確認的作業對應、`notes`。
