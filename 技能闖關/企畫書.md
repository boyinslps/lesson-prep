# 電腦急救站：學生電腦技能闖關網站　企畫書

> 版本 v0.1（2026-10-05 草案）｜狀態：等老師確認 §12 的待決事項，確認後開始施工

---

## 1. 一句話目標

做一個**闖關式**網站，讓學生把「複製貼上、純文字貼上、存圖片、改檔名、切換分頁、關掉彈出視窗」這類**上課一定會卡住的基本操作**，看一段短影片學會，再到網站的**模擬關卡**實際做一次，系統**自動判定**過關。學生輸入年級、班級、座號就能保留紀錄，完成指定的關卡後可以領**電子證書**。關卡之後可以**一直增加**，不用改主程式。

## 2. 為什麼要做

- 每學期前幾節課都花很多時間處理同樣的問題：貼上後格式亂掉、圖片存到哪裡找不到、檔名改不好、分頁太多找不到、被廣告視窗擋住。
- 這些技能分散在各單元，學生一次沒學會，之後就一直問。做成**可以隨時回來看的關卡**，學生卡住時可以自己查（老師只要說「去急救站做 B3」）。
- 過關要學生**真的做出那個動作**，不是只看完影片，老師在後台就看得到誰還沒會。

## 3. 使用情境

| 誰 | 什麼時候 | 做什麼 |
|---|---|---|
| 學生 | 開學第一、二節（必修關卡） | 照順序完成「新手上路」路線，領第一張證書 |
| 學生 | 平常上課卡住時 | 老師指定某一關，學生自己去看影片、做練習 |
| 學生 | 提早做完作業 | 自由挑戰其他類別、收集徽章、拚下一張證書 |
| 老師 | 課前／課後 | 後台看全班進度表，找出誰還沒過哪一關 |
| 老師 | 想到新的疑難雜症 | 跟 Claude 說「新增關卡：○○」，系統多一關，不影響舊紀錄 |

## 4. 網站架構

```
首頁（輸入 年級／班級／座號）
 └─ 技能地圖：依類別分區，關卡用線連起來表示先後順序
     ├─ 關卡頁（每關固定三段，一段一頁）
     │   1. 看：教學影片 30～60 秒（可重播、可放大）
     │   2. 練：同一個動作在模擬畫面上練一次，會提示
     │   3. 闖：沒有提示，做對自動過關 → 徽章動畫 → 存紀錄
     ├─ 我的紀錄：已過關卡、徽章、可領的證書
     └─ 證書頁：產生電子證書（可下載 PNG／列印）
教師後台（#admin）
 └─ 選年級班級 → 全班 × 關卡 進度表、單關通過率、重設某生某關
```

- 關卡狀態三種：🔒 鎖住（先修沒過）／⭕ 可挑戰／✅ 已過關。沒有先修的關卡一開始就能挑戰。
- 每關畫面維持精簡：一個核心動作、一個檢核，不塞額外題目（依學習單「別塞太滿」原則）。

## 5. 關卡分類與第一批清單

類別先分六區，代碼＝類別字母＋編號，之後新增的關卡接著編號即可。標 ★ 的是「新手上路」必修。

| 代碼 | 關卡 | 先修 | 網站上怎麼判定過關 |
|---|---|---|---|
| **A 滑鼠與鍵盤** ||||
| A1★ | 選取文字（拖選、雙擊選詞、Ctrl+A 全選） | — | 監聽選取範圍，要選到指定的那一句 |
| A2 | 拖曳物件到指定位置 | — | 拖放事件，放到目標區 |
| A3 | 中英切換、全形半形、Caps Lock | — | 在輸入框打出指定字串（含英數、半形） |
| A4 | 復原與取消復原（Ctrl+Z／Ctrl+Y） | A1 | 偵測按鍵＋文字恢復成原樣 |
| **B 複製與貼上** ||||
| B1★ | 複製貼上（Ctrl+C／Ctrl+V、右鍵選單） | A1 | 監聽 copy＋paste，貼上的內容等於指定文字 |
| B2 | 剪下與移動文字 | B1 | 原位置文字消失、新位置出現 |
| B3★ | 純文字貼上（Ctrl+Shift+V） | B1 | 從「有顏色粗體的範例」複製，貼進編輯區後**不能帶格式**（檢查貼入的 HTML） |
| B4 | 複製網址列的網址 | B1 | 開新分頁到指定頁、複製網址，貼回來比對 |
| **C 檔案與資料夾** ||||
| C1★ | 下載檔案、找到「下載」資料夾 | — | 下載關卡檔案 → 從選擇檔案對話框選回來上傳（檔案內有驗證碼） |
| C2★ | 檔案重新命名（F2、顯示副檔名） | C1 | 下載「作業.txt」→ 改成「4年1班05號.txt」→ 上傳，比對檔名與內容 |
| C3 | 建立資料夾、把檔案移進去 | C2 | 上傳時要用資料夾選取，檢查資料夾名稱與裡面的檔案 |
| C4 | 認識副檔名（.jpg .png .docx .pdf） | C2 | 拖曳分類小練習 |
| C5 | 刪掉的檔案從資源回收筒救回 | C3 | 影片教學為主＋上傳救回的檔案 |
| **D 圖片** ||||
| D1★ | 另存圖片（右鍵 → 另存圖片） | C1 | 存下網頁上的圖 → 上傳，比對圖片大小與雜湊值 |
| D2 | 複製圖片直接貼上 | B1 | 貼上事件裡要是圖片 |
| D3 | 螢幕截圖（Win+Shift+S）並貼上 | D2 | 貼上一張圖，尺寸合理且不是關卡原圖 |
| **E 瀏覽器與分頁** ||||
| E1★ | 開新分頁、切換分頁（Ctrl+Tab、點分頁） | — | 關卡開一個新分頁顯示密碼，切回來輸入（兩分頁用 BroadcastChannel 互通） |
| E2 | 關錯分頁救回來（Ctrl+Shift+T） | E1 | 被救回的分頁會通知原頁 |
| E3★ | 處理彈出視窗（廣告、Cookie、通知權限、假的「你中獎了」） | — | 網頁內模擬多種彈窗，要按對的關閉方式、不能按陷阱按鈕 |
| E4 | 網頁縮放與還原（Ctrl+滾輪、Ctrl+0） | — | 偵測縮放比例變化再回到 100% |
| E5 | 在網頁裡找字（Ctrl+F） | — | 在長文中找到指定詞，回答它出現幾次 |
| E6 | 離開全螢幕（F11／Esc） | — | 偵測進入再離開全螢幕 |
| **F 急救包** ||||
| F1 | 視窗不見了（Alt+Tab、Win+D） | E1 | 影片＋情境選擇題 |
| F2 | 打字一直蓋掉後面的字（Insert） | A3 | 模擬覆寫模式，修好後打出指定句子 |
| F3 | 網頁卡住、跑不出來（重新整理 F5） | — | 模擬卡住畫面，偵測重新整理後完成 |

網站做不到的部分（例如檔案總管裡的真實操作）一律用「**做完 → 把結果上傳回網站**」來檢核：上傳的檔名、內容、圖片雜湊值都能驗證，學生沒辦法只看影片就過關。

## 6. 證書與徽章

- **徽章**：每過一關得一個關卡徽章；某類別全過，得類別徽章。
- **證書分三階段**（條件寫在設定檔，不寫死關卡數量）：

| 階段 | 名稱 | 條件 |
|---|---|---|
| 一 | 電腦新手上路 | ★ 必修關卡全部通過 |
| 二 | 電腦小幫手 | 第一階＋每個類別至少過 2 關 |
| 三 | 電腦急救小醫生 | 當時開放的關卡全部通過 |

- 證書頒發時記下「當時的關卡清單」，**之後新增關卡不會讓已發的證書失效**；第三階的新關卡會顯示「新挑戰」提示。
- 證書在瀏覽器用 Canvas 產生 PNG，上面有年級班級座號、日期、證書編號（可在後台查驗）、右下角署名。學生可以在證書頁**自己輸入姓名**後列印，姓名不存進資料庫（沿用「只用數字識別」的規範）。

## 7. 學習紀錄

- 識別：沿用現有規範，**年級／班級／座號三個數字**，存在 localStorage（`wk_identity`），換關卡不用重打。
- Firestore 一位學生一份文件，讀寫都便宜：

```
skillQuest/{年級-班級-座號}
  grade, cls, seat
  levels: { "B3": { passedAt, tries, seconds } , ... }
  certs:  { "T1": { awardedAt, code, levelSnapshot:[...] } }
  updatedAt
```

- 沒網路時先存本機，連上後補上傳。
- 教師後台用 `grade+cls` 查全班，畫進度表；可重設某生某關（例如發現是別人幫忙做的）。
- 已知限制：沒有登入機制，懂技術的學生可能偽造紀錄；國小階段可接受，後台會顯示過關時間與嘗試次數，異常一眼看得出來。

## 8. 「可以一直加關卡」的設計

關卡全部是**資料**，主程式不用改：

```
技能闖關/
  企畫書.md、PROGRESS.md、README.md
  _原始碼/            ← 共用：地圖、關卡外框、存檔、證書、後台
  checkers/            ← 共用的判定器（貼上檢查、上傳檢查、按鍵檢查、彈窗、拖放、選擇題…）
  levels/
    B3_純文字貼上/
      level.json       ← 名稱、類別、先修、是否必修、判定器種類與參數
      practice.html    ← （選用）特殊關卡自訂的模擬畫面
      check.js         ← （選用）通用判定器不夠用時才寫
      assets/教學.mp4、封面.jpg
  build.py             ← 掃 levels/ 產生關卡總表 → 輸出可發布的網站
```

- 新增關卡＝新增一個資料夾，跑一次 build，地圖就多一關；先修關係由 `level.json` 的 `prereq` 自動畫線。
- 會另外寫一份 `引導規範/技能關卡設計規範.md`：關卡怎麼切（一關一個核心動作）、影片長度、判定原則（要偵測**真實動作**，不能只按「我完成了」）、命名規則。之後跟 Claude 說「新增關卡：○○」，就照這份規範產出。
- 可以停用關卡（`enabled:false`）但不刪，舊紀錄保留。

## 9. 教學影片怎麼做

| 畫面類型 | 做法 |
|---|---|
| 網頁、瀏覽器內的操作 | 沿用現有 `工作台/步驟影片工具`（Chrome 截圖＋游標動畫＋字卡 → MP4），**不需要 computer use**，晚上無人時也能做 |
| 桌面、檔案總管、右鍵選單、截圖工具 | 用 **computer use** 實際操作並逐步截圖，再丟進步驟影片工具合成；需要連續動作的（拖曳）改用 ffmpeg 錄螢幕再剪 |

- 錄影前準備一個乾淨的示範環境：`D:\示範` 資料夾、乾淨的 Chrome 設定檔、桌面不留個人檔案，避免拍到私人資料。
- 每支影片 30～60 秒，畫面紅框＋游標動畫＋一行字卡，結尾停在「換你試試看」。
- **限制**：computer use 每次使用都要老師按「允許」存取程式，而且電腦螢幕不能鎖定，所以**半夜自動執行時做不了桌面類影片**。這類影片會累積在「錄影待辦」清單，等老師在電腦前時一次錄完（大約一次 30 分鐘就能錄好一批）。

## 10. 每晚 12:00 自動施工

用 Claude 桌面版的排程任務（每天 00:00）：

```
1. 讀取用量：
   - 每週用量（weekly）已用 ≥ 60% → 寫一行「今晚略過」到日誌，結束
   - 5 小時用量已用 ≥ 50% → 同上
2. 讀 技能闖關/PROGRESS.md，挑下一個「工作包」
3. 做完一個工作包 → 自我檢查（打開頁面跑過判定）→ git commit（不 push）
4. 每做完一包重新讀用量：weekly ≥ 60% 或 5 小時 ≥ 85% 就收工
5. 寫施工日誌 技能闖關/施工日誌/YYYY-MM-DD.md：做了什麼、卡在哪、需要老師決定什麼
```

- **為什麼只 commit 不 push**：學生看的網頁要等老師早上看過再發布。老師說「push」時才照現有流程推到 lesson-prep＋pcclass。（如果希望半夜就直接發布，請在 §12 告訴我。）
- 前提：電腦開著、**不睡眠**、Claude 桌面版開著；權限要設成不用一直按允許，否則半夜會停在確認畫面。
- 目前方案是 Pro，5 小時額度用完一晚可能只做 1～2 個工作包；60% 這條線可以留 40% 給白天備課。
- 「工作包」的大小控制在一包約 30～60 分鐘可完成，例如「做 B3 關卡＋判定器＋影片腳本」。

## 11. 施工階段

| 階段 | 內容 | 工作包 | 完成標準 |
|---|---|---|---|
| P0 骨架 | 資料夾結構、`level.json` 格式、build.py、關卡外框（看／練／闖）、身分輸入、Firestore 存檔、技能地圖 | 3～4 | 放一個示範關卡能完整走完並存到紀錄 |
| P1 判定器 | 貼上檢查、上傳比對、按鍵偵測、彈窗模擬、拖放、跨分頁、選擇題 | 3 | 每種判定器有單元測試頁 |
| P2 必修 8 關 | ★ 關卡全部上線＋網頁類影片 | 4～5 | 第一階證書可以領 |
| P3 證書與後台 | Canvas 證書、證書編號查驗、教師進度表、重設 | 2～3 | 用假資料模擬一班 28 人看得到進度表 |
| P4 錄影補齊 | 老師在場時用 computer use 錄桌面類影片 | 人工 1～2 次 | 必修關卡都有影片 |
| P5 擴充 | 其餘關卡、新增關卡規範、日後持續增加 | 持續 | 新增一關只要新增資料夾 |

粗估 P0～P3 需要 12～15 個工作包，以每晚 1～2 包計算約 2～3 週；P4 需要老師在場。開放給學生的時間點建議是 P2＋P3 完成後。
